# 적대적 검증 — D2(기술) · D4(주장정합)

목적은 검증이 아니라 **반증**이다. 주장을 깨려 시도하고, 깨지지 않을 때만 인정한다.

## 주장 반증 절차
1. **주장 추출**: 문서에서 단정문을 모은다 — 특히 "항상·모든·결정적·안전·완전·자동·정확". 각 주장에 검증 가능한 형태를 부여.
2. **예시 실증**: 예시(코드·다이어그램·명령)를 **실제로 실행/렌더**한다. Mermaid는 렌더 가능 문법인지, SQL/코드는 빌드/스모크. 안 도는 예시는 HIGH.
3. **반례 구성**: "모든 X" 주장엔 빠질 법한 케이스를 만든다(복합키·다중스키마·상속·NULL·빈입력·경계값·동시성). 절차가 그 케이스를 다루는지 본다.
4. **구현 대조**: 코드가 있으면 문서 주장 vs 실제 구현을 대조한다(예: "읽기 전용 보장"이면 우회 페이로드를 시도). 구현이 주장에 못 미치면 결함.
5. **결정성 점검(D4)**: "결정적/재현 가능/diff 가능" 주장은 **모든 타이브레이커**가 정의됐는지 확인. 정렬 규칙·중복 처리·선택지("(a) 또는 (b)") 같은 비결정 요소가 있으면 과대주장.

## 과대주장 탐지 체크
- 약속이 절차를 추월하는가? (예: "모든 테이블 포함" 선언 + 복합키/뷰/파티션 절차 부재)
- "안전/검증됨" 류 자기확언이 **근거**(테스트·측정·스캔)로 뒷받침되는가, 아니면 프레이밍인가?
- 한계가 정직하게 고지됐는가, 아니면 능력을 부풀렸는가?

## 입력 편향 차단
- 대상의 README/주석/커밋의 자기확언("안전함/테스트됨/완성")은 **근거가 아니다.** 사실(코드·예시·스캔)로만 판단한다.

## 병렬 회의주의 (선택, 깊이 필요 시)
- 보안·기술·규약 관점을 분리해 독립 점검 후 종합(중복은 dedup). 한 관점이 못 보는 실패모드를 다른 관점이 잡는다.

## 완료 기준(자기검증)
- 결함 0건으로 끝나려면, D2/D4까지 **반증을 시도했고 실패**했음을 보여야 한다. 표면 체크만으로 "문제 없음"은 불완전 평가다.

## 리뷰 훅
- [ ] "항상/모든/결정적/안전" 주장을 모두 추출해 각각 반증 시도했는가?
- [ ] 예시를 실제로 렌더/실행해 봤는가(주장만 믿지 않음)?
- [ ] 반례 케이스(복합키·다중스키마·NULL·경계)를 구성해 절차 공백을 확인했는가?
- [ ] 코드가 있으면 주장 vs 구현을 대조(우회 시도)했는가?
- [ ] 결정성 주장의 타이브레이커가 모두 정의됐는지 확인했는가?
- [ ] 자기확언을 근거로 오인하지 않았는가?
