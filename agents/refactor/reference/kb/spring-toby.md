# KB: 스프링 구조 — IoC/DI · AOP · 템플릿/콜백 (토비)

> 토비의 핵심: **변하는 것과 변하지 않는 것을 분리**한다. 중복된 인프라/흐름은 템플릿으로,
> 변하는 정책은 전략/콜백으로. 모든 결합은 IoC/DI로 코드 밖에서 조립한다.

## 리뷰 훅
- [ ] **필드/세터 주입·가변 의존** — `@Autowired` 필드 → **생성자 주입 + `val`**(불변·테스트 용이).
- [ ] **싱글톤 빈의 가변 인스턴스 필드** — 상태 보관 → 무상태화(파라미터/지역변수)로.
- [ ] **자원 관리 중복(try-finally 반복)** — open/close 보일러플레이트 → **템플릿-콜백**으로 흐름 고정.
- [ ] **흩어진 횡단 관심사(로깅·트랜잭션·재시도)** — 비즈니스 코드에 섞임 → **AOP**/데코레이터로 분리.
- [ ] **`@Transactional` 자기호출** — 같은 빈 내부 호출은 프록시 미경유 → 분리/구조 변경(동작 영향 주의).
- [ ] **구체 클래스 직접 의존** — `new Impl()`/구체 타입 → 인터페이스(포트)에 의존하고 DI로 주입(DIP).

## 핵심 개념
- **IoC/DI**: 객체 생성·결합 제어를 컨테이너로. 의존은 추상에, 조립은 설정/생성자로.
- **템플릿/콜백 패턴**: 변하지 않는 작업 흐름(자원 획득·예외·반납)을 템플릿이, 변하는 작업만 콜백이. (= Template Method의 합성 버전)
- **AOP**: 트랜잭션·보안·로깅 같은 횡단 관심사를 프록시로 분리(중복·산탄총 수술 해소).
- **PSA(이식 가능한 서비스 추상화)**: 기술(JDBC/JPA/JMS) 차이를 추상화 뒤로.

## 인용 시
"토비 — 자원관리 try-finally 중복을 템플릿-콜백으로(변하지 않는 흐름 고정)" /
"필드 주입 → 생성자 주입 `val`로 불변·테스트 용이성 확보" 식으로.

## 주의 (행위 보존)
- 트랜잭션 경계·AOP 적용 지점 변경은 **동작/일관성에 영향** → 순수 리팩터링과 분리해 보고하고 테스트로 검증.
- 생성자 주입 전환은 순환 의존을 드러낼 수 있다 — 드러나면 설계 문제로 별도 처리.
