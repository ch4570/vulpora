# 부하 테스트 대상 안전과 허가 범위

부하는 대상과 같은 네트워크·DB·외부 연동을 공유하는 모든 것에 영향을 준다. 허가는 대상 소유자의 것이고,
요청자가 대신 줄 수 없다.

## 환경 분류와 판정

| 분류 | 의미 | 판정 |
|---|---|---|
| `local` | 사용자의 로컬 프로세스·컨테이너 | 진행 |
| `ephemeral` | 이 실행이 띄운 컨테이너·프로세스(ID 기록) | 진행 |
| `dedicated-test` | 부하 테스트 전용으로 운영되는 환경(공유 사용자 없음) | 진행, 근거 기록 |
| `authorized-shared` | 다른 사용자가 있는 스테이징·QA 환경 | 소유자 승인·시간대·최대 부하·중단 기준이 계획에 있을 때만 |
| 운영, 제3자·외부 SaaS, 소유 미확인 호스트 | — | 거부 |

- 대상이 호출하는 외부 연동(결제, 메시지, 메일, SMS)은 stub이나 샌드박스로 막혀 있는지 확인한다. 막을 수 없으면
  해당 흐름을 시나리오에서 빼고 한계로 적는다.
- DNS 이름이나 설정이 운영을 가리키면(예: `prod`, 실제 서비스 도메인) 사용자 진술보다 증거를 우선한다.

## 중단 기준

- k6 `thresholds`에 `abortOnFail: true`를 둔 오류율·지연 기준을 넣어 기준을 넘으면 실행이 멈추게 한다.
  `delayAbortEval`로 워밍업 직후의 오탐을 피한다.
- `authorized-shared`는 소유자가 정한 최대 부하를 계획의 상한으로 쓰고, 그 이상 올리지 않는다.

## 리뷰 훅

- [ ] 환경 분류와 근거(컨테이너 ID, 전용 환경 문서, 소유자 승인)가 `plan.json`에 있다.
- [ ] 운영·제3자 대상이 아니다.
- [ ] 외부 연동이 stub·샌드박스로 막혔거나 시나리오에서 빠졌다.
- [ ] 중단 기준이 스크립트의 `abortOnFail` threshold로 구현됐다.
