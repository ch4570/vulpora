# 사용자 결정형 소크라테스식 질문 정책

- 질문이 실제로 필요할 때만 한 사용자 턴에 결정 하나를 묻는다. Generic freeze confirmation은
  만들지 않는다. 질문을 보냈다면 즉시 턴을 끝내고 다음 사용자 메시지를 기다린다.
- 현재 명확도와 모호성 점수, 가장 중요한 미결정 영역, 안전할 때 현재 상태로 구현할 수 있다는 안내를
  사용자에게 보여준다. Round, gate, skip, freeze, ledger 같은 내부 용어만 숨긴다.
- clarification 질문 초안은 사용자에게 보내기 전에 trusted runtime catalog의
  정확한 `korean-dev-writer`로 윤문한다.
  blocking unknown과 보존할 의미를 함께 넘기고, 반환 문장이 같은 결정 축만 묻는지 다시 대조한다.
  의미가 바뀌면 보존 조건을 좁혀 1회만 재요청하며 스킬이 없으면 fallback 없이
  `SKILL_UNAVAILABLE:korean-dev-writer`로 중단한다.
- 질문 하나는 하나의 blocking unknown과 결정 축만 다룬다. 여러 필수 입력을 쉼표나 접속사로 묶어
  문법적으로만 한 문장인 복합 질문을 만들지 않는다.
- 윤문 후 의미, decision focus, 구체성, 식별자, 제약, frame shape를 원문과 대조한다. 추상적인 시스템
  범위만 묻지 말고 install target이나 scope consequence처럼 답이 바꾸는 구체 대상을 이름으로 남긴다.
- 가역적 결정에는 repository evidence와 최소 변경 원칙에 근거한 `추천 기본값:`을 한 줄로 밝히고,
  무엇이 달라지는지 설명한다. 질문에는 `기본값으로 진행`과 사용자가 직접 쓸 수 있는 다른 기준을 함께
  열어 둔다. 추천은 권한·파괴적 작업·공개 계약·중대한 데이터 모델 결정을 대신하지 않는다.
- 번호 목록, A/B/C, 체크박스, “다음 중 선택”처럼 답을 폐쇄하는 객관식은 사용하지 않는다. 서로 배타적인
  답변 예시를 짧게 보여주는 것은 허용하지만, 항상 추천 이유와 자유 입력 경로를 함께 둔다.
- 목표와 완료 기준 → 범위 → 제약과 호환성 → 권한과 위험 → 구현 선호 순으로 묻는다.
- repository의 read-only 탐색으로 답할 수 있는 질문은 사용자에게 넘기지 않는다.
- 각 질문은 연결된 blocking unknown id와, 답에 따라 갈리는 결정을 가진다.
- 매 답변 뒤 명확도 점수를 다시 계산하고, 아직 resolved되지 않은 축 중 기대 점수 개선 폭이 가장 큰
  질문을 다음 한 문항으로 고른다.
- 고정된 총 질문 상한을 두지 않는다. 사용자가 더 명확히 하기를 선택하고 다음 질문의 정보 가치가 있을
  때만 이어간다. 한 답변이 불충분해도 같은 질문을 반복하지 말고 남은 결정점을 다른 열린 질문으로
  좁힌다. 사용자가 현재 상태로 구현하라고 하면 숫자 threshold만 우회하고 가정·위험을 기록한다.
- 작고 가역적인 결정은 `assumptions[]`로 옮길 수 있다. 공개 계약, 데이터 손실, 비용 발생, 외부 전송,
  권한 확대, 보안 수준 저하는 가정할 수 없다.

## 리뷰 훅

- [ ] 질문마다 하나 이상의 blocking unknown을 제거하는가?
- [ ] 앞선 답변과 저장소 증거로 이미 알 수 있는 것을 다시 묻지 않는가?
- [ ] 현재 명확도와 모호성의 합이 100이고 사용자에게 그대로 보이는가?
- [ ] 한 턴에 결정 축이 정확히 하나이고 사용자가 기본값 수락 또는 다른 기준을 쉽게 답할 수 있는가?
- [ ] 가역적 결정의 추천 기본값에 근거·영향이 있으며 폐쇄형 객관식이나 여러 질문을 제시하지 않았는가?
- [ ] 한 질문 안에 여러 결정 축이나 입력 체크리스트를 숨기지 않았는가?
- [ ] 현재 점수·통과선·가장 약한 축이 canonical projection에 기록되고 점수는 대화 frame에도 보이는가?
- [ ] 질문이 `korean-dev-writer` 윤문과 의미 보존 대조를 통과했는가?
- [ ] 사용자의 진행 요청이 가역적 불확실성만 수용하고 비우회 blocker는 보존하는가?
- [ ] clarification frame을 노출한 뒤 실제 사용자 답변을 기다리는가?
