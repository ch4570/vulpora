# KB: 테스트 케이스 명세 포맷 · 추적성 매트릭스

이 문서는 이 에이전트가 **파일로 산출하는 케이스 명세의 형식**을 고정한다. 아래 컬럼/키 집합은
본 저장소의 내부 규약이며 특정 표준(ISTQB 등)의 강제 양식이 아니다(정직 라벨). 형식의 *근거*는
ISTQB 케이스 구성요소(전제·입력·기대결과)와 추적성 개념을 차용한다.

## 1. 테스트 케이스 표 (필수 컬럼)
| 컬럼 | 의미 | 규칙 |
|---|---|---|
| **케이스 ID** | 고유 식별자 | `TC-{영역}-{번호}` (예: `TC-ORDER-001`). 안정적·중복 금지 |
| **요구/위험 링크** | 추적 대상 | 요구 ID 또는 위험 항목(추적성 매트릭스 키) |
| **전제(Precondition)** | 시작 전 성립해야 할 상태 | 관찰/설정 가능해야 함. 자유서술 지양 |
| **입력(Input)** | 투입 데이터/파라미터 | 합성 데이터만(실데이터·PII 금지) |
| **단계(Steps)** | 수행 순서 | 선언적. 번호 매김 |
| **기대결과(Expected)** | 관찰 가능한 결과 | 반환값/상태/상호작용. "에러 안 남" 금지 |
| **우선순위** | P0/P1/P2 | `risk-coverage.md` 등급 |
| **유형(Type)** | 정상/비정상/경계/엣지 | + 적용 기법(EP/BVA/결정표/상태전이/페어와이즈) |
| **레벨(Level)** | 단위/통합/E2E | `test-strategy-pyramid.md` 기준 |

### 예시 (일반 엔티티 `Order`)
| 케이스 ID | 요구/위험 | 전제 | 입력 | 단계 | 기대결과 | 우선순위 | 유형 | 레벨 |
|---|---|---|---|---|---|---|---|---|
| TC-ORDER-001 | REQ-ORD-1 | 재고 10 | qty=2 | 주문 생성 호출 | 주문 CREATED, 재고 8 | P0 | 정상(해피) | 통합 |
| TC-ORDER-002 | REQ-ORD-1 | 재고 1 | qty=5 | 주문 생성 호출 | 거부, "재고 부족" | P0 | 비정상(네거티브) | 통합 |
| TC-ORDER-003 | REQ-ORD-2 | 재고 99 | qty=0/1/99/100 | 주문 생성 | 0·100 거부, 1·99 허용 | P1 | 경계(BVA) | 단위 |
| TC-ORDER-004 | RISK-ORD-STATE | status=DELIVERED | cancel | 취소 시도 | 거부(무효 전이) | P1 | 엣지(상태전이) | 단위 |

## 2. 추적성 매트릭스 (요구 ↔ 케이스)
양방향 매핑으로 **케이스 없는 요구**(커버리지 공백)와 **요구 없는 케이스**(근거 불명)를 드러낸다.

| 요구 ID | 설명 | 커버 케이스 | 상태 |
|---|---|---|---|
| REQ-ORD-1 | 재고 내 주문 생성/거부 | TC-ORDER-001, 002 | ✅ 커버 |
| REQ-ORD-2 | 수량 범위 1~99 | TC-ORDER-003 | ✅ 커버 |
| REQ-ORD-3 | 결제수단별 처리 | — | ⚠️ **공백** |
| RISK-ORD-STATE | 잘못된 상태 전이 차단 | TC-ORDER-004 | ✅ 커버 |

- `⚠️ 공백` 행은 **추가 케이스 도출 또는 의식적 제외 사유**를 남긴다.
- 고위험 항목이 공백이면 P0로 즉시 보강.

## 3. 산출 파일 배치 (권장)
- 케이스 명세·매트릭스는 대상 저장소의 테스트 문서 위치(예: `docs/test-cases/` 또는 PR 설명)에 둔다.
  프로젝트에 전역 E2E 카탈로그 규약이 있으면 **그 규약을 따르고 자체 카탈로그를 새로 만들지 않는다.**
- 실행 가능한 시나리오는 Gherkin(`acceptance-criteria-gherkin.md`)으로 표현해 실행 에이전트에 인계한다.
- 사람용 산출물과 같은 basename의 `*.qa-plan.json`을 함께 작성하고 번들의
  `qa/reference/qa-test-plan-contract.md` 및 `qa/scripts/validate-test-plan.js`로 검증한다. JSON은
  케이스 ID, 요구·위험 양방향 추적성, P0 근거·커버리지, 합성 데이터, 실행 인계 수명주기의 단일
  기계 검증 입력이다.

## 리뷰 훅
- [ ] 모든 케이스에 **케이스 ID·전제·입력·단계·기대결과·우선순위·유형·레벨**이 채워졌는가.
- [ ] 기대결과가 **관찰 가능**한가("정상 동작/에러 없음" 금지).
- [ ] 입력/전제에 **실데이터·PII가 없는가**(합성 데이터만).
- [ ] **추적성 매트릭스**가 요구↔케이스를 양방향으로 연결하는가.
- [ ] **케이스 없는 요구**(공백)와 **요구 없는 케이스**가 드러나는가.
- [ ] 공백 행에 보강 계획 또는 의식적 제외 사유가 있는가.
- [ ] `*.qa-plan.json`이 validator exit 0인가(P0 공백은 제외 사유로 우회할 수 없음).
