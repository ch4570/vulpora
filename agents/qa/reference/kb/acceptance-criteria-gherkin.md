# KB: 인수기준 · Gherkin

인수기준(Acceptance Criteria)은 "이 요구가 충족되었다"를 판정하는 관찰 가능한 조건이다.
Gherkin은 그 조건을 **Given-When-Then** 구조로 표현하는 표준 문법이며, 실행 에이전트가
시나리오로 받을 수 있는 형태다.

## 핵심 키워드
| 키워드 | 의미 |
|---|---|
| `Feature` | 검증 대상 기능 묶음 |
| `Scenario` | 하나의 구체 사례(케이스) |
| `Given` | **전제/사전 상태**(이미 성립한 컨텍스트) |
| `When` | **행위/이벤트**(검증 대상 동작 — 한 시나리오에 하나로) |
| `Then` | **관찰 가능한 기대결과**(출력/상태/상호작용) |
| `And` / `But` | 같은 종류 단계의 연결 |
| `Background` | 시나리오 공통 `Given` 추출 |
| `Scenario Outline` + `Examples` | 같은 시나리오를 **표의 값으로 데이터 구동** 반복 |

## 작성 규칙 (좋은 인수기준)
1. **하나의 When** — 한 시나리오는 하나의 행위만 검증한다(여러 행위는 시나리오를 나눈다).
2. **관찰 가능한 Then** — "정상 동작"이 아니라 검증 가능한 결과를 단정한다(상태/응답/이벤트).
3. **선언적으로** — UI 클릭 절차가 아니라 "무엇을 달성하는가"를 기술(구현 변경에 강건).
4. **결정적** — 같은 Given/When이면 항상 같은 Then. 시계·난수 의존 금지.

## 예시 (일반 엔티티)

### 단일 시나리오
```gherkin
Feature: 주문 생성

  Scenario: 회원이 재고 있는 상품을 주문하면 주문이 생성된다
    Given 회원 "M-100" 이 로그인되어 있다
    And 상품 "P-1" 의 재고가 10개 있다
    When 회원이 상품 "P-1" 을 2개 주문한다
    Then 주문이 "CREATED" 상태로 생성된다
    And 상품 "P-1" 의 재고가 8개로 감소한다
```

### 네거티브 시나리오
```gherkin
  Scenario: 재고보다 많이 주문하면 거부된다
    Given 상품 "P-1" 의 재고가 1개 있다
    When 회원이 상품 "P-1" 을 5개 주문한다
    Then 주문은 생성되지 않는다
    And "재고 부족" 오류가 반환된다
```

### 시나리오 아웃라인 (BVA를 표로 — 데이터 구동)
```gherkin
  Scenario Outline: 주문 수량 경계값 검증 (허용 1~99)
    When 회원이 상품 "P-1" 을 <수량>개 주문한다
    Then 결과는 "<결과>" 이다

    Examples:
      | 수량 | 결과   |
      | 0    | 거부   |
      | 1    | 허용   |
      | 99   | 허용   |
      | 100  | 거부   |
```

## 케이스 → Gherkin 매핑
- 케이스 명세 표의 `전제`→`Given`, `입력/단계`→`When`, `기대결과`→`Then`.
- EP/BVA로 뽑은 값들은 `Scenario Outline`의 `Examples` 행으로 자연스럽게 전개된다.

## 리뷰 훅
- [ ] 각 시나리오의 `When` 이 **하나의 행위**인가(복수 행위는 분리).
- [ ] `Then` 이 **관찰 가능한 결과**(상태/응답/이벤트)인가("정상 동작" 같은 모호 표현 금지).
- [ ] `Given` 이 검증 대상 행위 이전의 **전제**만 담는가(행위가 Given에 섞이지 않았는가).
- [ ] 데이터 변형이 있는 케이스를 `Scenario Outline`+`Examples`로 묶어 중복을 줄였는가.
- [ ] 해피패스뿐 아니라 **네거티브/경계 시나리오**가 포함되었는가.
- [ ] 시나리오가 선언적이고 결정적인가(UI 절차·시계/난수 의존이 없는가).
