# KB: flaky 안정성

flaky = 코드 변경 없이 같은 테스트가 통과/실패를 오가는 상태. 신뢰를 무너뜨리므로 **은폐가 아니라
격리**한다.

## flaky 원인
| 원인 | 예 |
|------|-----|
| 비결정적 대기 | 고정 `sleep`로 비동기 완료를 가정 |
| 공유 가변 상태 | 테스트 간 데이터/세션 오염(→ test-data-lifecycle.md 격리) |
| 타이밍/경합 | 애니메이션·네트워크 지연·렌더 타이밍 |
| 순서 의존 | 앞 테스트의 잔여 데이터에 의존 |
| 외부 의존성 | 제어 불가 외부 시스템(→ fixtures-environment.md 모킹) |

## 결정적 대기 (고정 sleep 금지)
- Playwright는 액션 전 **auto-wait**(요소 actionable까지 대기)한다. 명시 대기는 조건 기반:
  요소 가시성/상태, 응답 도착, **데드라인 폴링**(기한 내 조건 충족까지 반복).
- 고정 sleep은 느리면 깨지고 빠르면 낭비 — 금지.

## 격리(쿼런틴)와 재시도 정책
- flaky로 판정된 시나리오는 **격리**해 본 스위트의 신호를 더럽히지 않게 하고, 원인 분석 후 QA에 보고.
- 재시도가 필요하면 프레임워크 설정(`retries`)으로 **명시**하고, 재시도로 통과한 케이스는 **flaky로
  별도 추적**한다 — 자동 재시도로 결함을 "통과처럼" 가리지 않는다(무재시도 기본).

## 리뷰 훅
- [ ] 비동기/UI 대기가 **결정적**인가(고정 sleep 없음, 조건/데드라인 폴링).
- [ ] flaky를 자동 재시도로 **은폐**하지 않는가 — 격리 후 QA 보고하는가.
- [ ] 재시도를 쓴다면 명시 설정 + flaky 별도 추적인가.
- [ ] flaky 원인이 공유 상태/순서 의존이면 격리(고유 데이터)로 해소했는가.
