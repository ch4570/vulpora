# KB: 픽스처·환경 분리

## 픽스처
- 픽스처는 테스트가 필요로 하는 **환경·상태의 setup/teardown을 캡슐화**한다. setup에서 자원을
  생성하고 teardown에서 정리해 누수를 막는다(Playwright fixtures).
- 픽스처는 **격리** 단위다 — 각 테스트가 독립된 픽스처 인스턴스를 받아 상호 오염을 피한다.

## 환경 분리 (운영 절대 금지)
| 환경 | E2E 대상 가능? |
|---|---|
| 로컬 compose / 일회성 컨테이너 | ✅ 격리·전용 |
| 전용 스테이징(격리 보장 시) | 조건부 |
| **운영 / 공유 환경** | ❌ **절대 금지** — 시드/정리 명령 불가 |

- 시드·teardown은 격리 환경에서만. 운영 데이터는 대상이 아니다(원칙 §1·§4).

## 시드 데이터
- **합성·라운드 값**만 사용. 실제 사용자/PII 금지. 예: `Member` ID `900..999`, `Order` ID `100..199`
  같은 둥근 합성 식별자.
- 테스트별 **고유** 시드로 격리(→ test-data-lifecycle.md). 시드 목록은 정리 입력으로 기록.

## 외부 의존성 모킹/스텁
- 제어 불가능한 외부 시스템(서드파티 API·결제·메일)은 **테스트 더블**(스텁/모킹)로 대체해 결정성·격리
  확보(Fowler, Test Double).
- 단, E2E의 목적은 핵심 경로의 **실제 통합**을 검증하는 것 — 무엇을 실제로 두고 무엇을 모킹할지는
  시나리오 의도에 따른다. 핵심 통합 경로를 통째로 모킹하면 E2E의 의미가 사라진다.

## 리뷰 훅
- [ ] 실행 환경이 **격리**(compose/일회성 컨테이너)인가 — 운영/공유 환경이 아닌가.
- [ ] 시드 데이터가 **합성·고유**인가(실제 PII 없음, 테스트별 격리).
- [ ] 픽스처가 setup/teardown을 캡슐화해 자원 누수가 없는가.
- [ ] 외부 의존성 모킹 범위가 적절한가(핵심 통합 경로를 통째로 모킹하지 않음).
