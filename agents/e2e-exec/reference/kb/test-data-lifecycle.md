# KB: 테스트 데이터 라이프사이클 — 데이터 클렌징

> 이 KB는 이 에이전트의 **핵심 책무**다: 테스트가 만든 데이터를 실행 후 안전하게 정리해 환경을
> 원상복구한다. `source`는 테스트 더블(외부 의존성 격리)·테스트 데이터 관리 실무.
> **정직 라벨**: 아래 표의 구체 정리 절차는 공식 표준이 아니라 **내부 실무 규칙**이다(미검증).

## 단계: setup/seed → execute → verify → teardown/cleanse
| 단계 | 행위 |
|------|------|
| setup/seed | 테스트별 **고유** 데이터를 생성. 생성한 ID·인덱스 문서·토픽 메시지를 **기록** |
| execute | 시나리오 실행(데이터 변경 발생) |
| verify | 기대 동작 검증 |
| teardown/cleanse | 생성·변경분을 **모두** 되돌려 원상복구 + 정리 검증 |

## 정리 방식: 트랜잭션 롤백 vs 명시 삭제
| 변경 위치 | 정리 방식 | 비고 |
|---|---|---|
| 트랜잭션 경계 안 DB 변경 | **트랜잭션 롤백** | 가장 싸고 안전. 커밋 안 함 |
| 커밋된 DB 행 | **명시 DELETE**(기록한 ID 기준) | 롤백 불가 영역 |
| 검색 인덱스 문서(예: Order 색인) | 명시 삭제(문서 ID/쿼리) | 외부 시스템 |
| 메시지 토픽 / 큐 | 소비·오프셋 정리 또는 전용 토픽 폐기 | 잔여 메시지 = 오염 |
| 캐시 / 파일 | 키 무효화 / 파일 제거 | |

## 격리·멱등·검증·고아 방지
- **격리**: 테스트별 고유 데이터(예: `Member` 고유 ID, `Order` 고유 키)로 상호 오염 차단.
- **멱등**: 정리는 여러 번 돌려도 안전 — 이미 없는 리소스 삭제 시도는 무해해야 함. 부분 실패·중단 후
  재실행에도 원상복구.
- **정리 검증**: teardown 후 카운트=시드 전 값, 토픽/인덱스 잔여 0 확인. 검증 없으면 미완료.
- **고아 데이터 방지**: 기록한 리소스를 빠짐없이 제거. 실행 중단에도 다음 실행 전 재진입 정리 가능하게.

## 리뷰 훅
- [ ] 시드 시 생성/변경 리소스를 **기록**했는가(정리 입력 존재).
- [ ] 변경마다 정리 방식(롤백 / 명시 삭제)을 짝지었는가 — 커밋·외부 시스템은 명시 삭제인가.
- [ ] 데이터가 **테스트별 고유**(격리)인가 — 공유 가변 상태 오염 위험은 없는가.
- [ ] 정리가 **멱등**한가(재실행·부분실패 안전).
- [ ] teardown 후 **정리 검증**(잔여 0)을 수행했는가.
- [ ] 고아 데이터가 남지 않는가(빠짐없이 제거 + 재진입 정리 가능).
