# Vulpora v1.0.0 release checks

This document defines the reproducible distribution checks and their limits. Publication status is recorded
in the GitHub release and [issue ledger](issue-resolution.md), not inferred from a local test command.

## Source and package

```sh
npm run check:release
npm test
npm run test:routing
(cd mcp/nl-sql && npm ci --ignore-scripts && npm audit && npm test && npm run typecheck)
```

The source gate requires a clean committed snapshot, aligned package/plugin/VERSION metadata, manifest
consistency, public-safe source, and the complete discovered offline contract suite. The npm integration runs
the extracted package's lifecycle gate, full-catalog install/doctor/removal, inert npm install/uninstall,
single-command dispatch, and tarball content checks. The root wrapper has no dependencies or lockfile;
`npm audit` belongs in the separately locked MCP package.

The publication inventory must contain only reviewed tracked files. It excludes Git metadata, local state,
credentials, installed dependencies, raw research, private audit artifacts, and generated bytecode. The source
neutrality check rejects private identifiers/local paths and the retired product spelling. V1 has one executable,
`vulpora`, and one namespace; no alternate product alias is distributed.

## Public history

Preserve development history privately because its old blobs include private identifiers. Publish the reviewed
current source through a fresh public history with a public-safe author. Inspect the resulting source archive,
package inventory, license/NOTICE, and Git metadata before changing visibility or creating the v1.0.0 release.
User authorization for this release includes repository publication and npm publication; npm still requires an
authenticated publishing account. Never put credentials or raw model transcripts in release artifacts.

## Runtime evidence

The [session report](../evals/token-efficiency/README.md) records two actual Codex fixtures and observed usage.
Requested model/effort are settings, not authenticated backend identity. Runtime output is a candidate until the
primary independently checks files and acceptance. New sessions omit the parent transcript but may still have
substantial startup instructions and repeated input. Source-token counts are not provider billing.

Offline tests do not replace real database integration, Claude execution, browser acceptance for a product task,
or broad live model quality evaluation. OpenCode remains experimental. Explicit audits retain their native
receipt contract; the independent-session transport does not forge native child evidence.

## Operational evaluation boundary

Issue #25 remains operationally incomplete until an operator provides and verifies isolated runners with actual
filesystem/network/process probes, distinct trusted signing identities, protected policy delivery, immutable
original evidence, provider-enforced budgets, and repeated live security trials that pass the defined criteria.
An environment flag or synthetic signed receipt is insufficient. Promotion remains blocked; see
[the trust contract](eval-trust-boundaries.md).
