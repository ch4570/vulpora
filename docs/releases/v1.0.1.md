# Vulpora v1.0.1 — 초기화 라우팅과 설치·세션 처리 수정

날짜: 2026-09-08 · 이전 버전: v1.0.0

Java/Spring 프로젝트가 Gradle Kotlin DSL과 빌드 보조 코드 때문에 Kotlin/Spring으로 분류되던 문제를
수정했습니다. Codex 설치 지침의 개인 홈 경로 고정과 독립 세션의 검증·예산 처리도 보완했습니다.

## 수정 및 개선

- **모듈별 JVM 라우팅:** 실제 Java/Kotlin 소스와 해당 모듈의 빌드 설정을 함께 판단합니다.
  `build.gradle.kts`, `settings.gradle.kts`, `buildSrc`, Gradle convention plugin은 Kotlin 애플리케이션
  근거로 삼지 않습니다. 혼합 프로젝트는 변경 대상 모듈·파일 언어에 따라 안내하며, Java 작업에는
  Kotlin 전용 작성·테스트 스킬을 연결하지 않습니다. 설치된 번들, 평가 fixture, 숨김 작업 산출물도
  서비스 스택 근거에서 제외합니다. [PR #5](https://github.com/ch4570/vulpora/pull/5)
- **이식 가능한 Codex 설치 지침:** user 설치의 28개 TOML에서 `~/.codex/...`, `~/.agents/skills/...`를
  사용하고 파일을 읽기 전에 현재 사용자 홈으로 해석하도록 지시합니다. 명시적인 project scope는
  프로젝트 절대 경로를 유지합니다. 권한·샌드박스 설정과 사용자 수정 파일의 덮어쓰기 보호를 유지합니다.
  [PR #5](https://github.com/ch4570/vulpora/pull/5)
- **난이도별 세션 라우팅과 예산:** 작은 범위의 작업에서 Luna를 선택하고, 검증 실패 시 정해진 경로로
  상위 모델을 사용하는 라우팅과 공유 세션 예산을 보강했습니다. 요청한 모델과 실제 공급자 사용량을
  구분해 기록합니다. [PR #2](https://github.com/ch4570/vulpora/pull/2)
- **입출력과 실패 처리:** 선택형 편집 제안 모드로 응답 범위를 제한하고 제안 적용 및 파일 모드 보존을
  검증합니다. 잘못된 출력 schema는 세션 실행 전에 거부하고, 금지된 도구 호출은 조기에 중단합니다.
  중단·실패한 호출의 사용량과 예산 상태를 성공 결과로 숨기지 않습니다.
  [PR #3](https://github.com/ch4570/vulpora/pull/3), [PR #4](https://github.com/ch4570/vulpora/pull/4)

## 업데이트

GitHub 태그로 CLI를 설치합니다. CLI 설치만으로 기존 스킬·에이전트가 자동 갱신되지는 않습니다.

```sh
npm install --global 'git+https://github.com/ch4570/vulpora.git#v1.0.1'
```

Codex user scope에 전체 catalog를 설치한 경우 다음 명령으로 갱신하고 확인합니다.

```sh
vulpora setup --runtime codex --scope user
vulpora doctor --runtime codex --scope user
```

Claude Code의 직접 설치는 `--runtime claude-code`를 사용합니다. project 또는 선택 설치는 기존
`--scope`, `--target`, selector를 유지합니다. Claude marketplace plugin 설치는 Claude의 plugin
업데이트 경로를 사용합니다. 갱신 후 대상 저장소에서 Codex는 `$vulpora-init`, Claude Code는
`/vulpora-init`을 다시 실행해 `AGENTS.md`의 Vulpora 블록을 새로 생성합니다.

## 호환성과 검증 범위

- 기존 14개 pack, 28개 agent, 62개 skill ID와 receipt 계약을 유지합니다. 저장소 버전은 `1.0.1.0`,
  npm 형식 패키지와 Claude plugin 버전은 `1.0.1`입니다.
- 수정 전 회귀 테스트로 오분류를 재현했고, 확장한 초기화 테스트 12개와 기존 shell 계약이 통과했습니다.
  Java 1,204개와 빌드 보조 Kotlin 2개를 가진 격리 재현 저장소에서 패키지 업데이트 후 Java/Spring 판정,
  수동 지침 보존, 멱등성, `--dry-run`, `--check`를 확인했습니다.
- Codex 설치 호환성 14개와 CLI 검사 23개가 통과했습니다. 28개 TOML의 설정을 보존하면서 구체 경로
  참조 134개와 와일드카드 참조 14개가 같은 대상을 가리키는지 확인했습니다.
  [설치 검증 기록](https://github.com/ch4570/vulpora/pull/5)
- 초기화 오류가 제보된 실제 서비스 저장소는 로컬에서 찾지 못해 직접 검증하지 못했습니다. 스택 감지는
  정적 분석이며 Gradle/Maven 실행이나 동적·상속 빌드 설정의 완전한 해석을 보장하지 않습니다.
- 최종 릴리즈 커밋의 CI 결과와 배포 파일 검증 결과는
  [GitHub Release](https://github.com/ch4570/vulpora/releases/tag/v1.0.1)에 기록합니다.

## 배포 파일

- `vulpora-1.0.1.tgz`: npm 형식 설치 패키지.
- `vulpora-source-1.0.1.tar.gz`: 릴리즈 태그의 소스 압축본.
- `SHA256SUMS`: 두 첨부 파일의 SHA-256 체크섬.

```sh
shasum -a 256 -c SHA256SUMS
npm install --global ./vulpora-1.0.1.tgz
```

npm registry 게시는 기존과 같이 보류합니다. 이번 배포는 GitHub Release와 첨부 설치 패키지입니다.
