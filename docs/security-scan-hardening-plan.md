# 보안 점검·위험 제거 확장 계획

## 목표와 경계

예시 취약점 검색에 그치지 않고 진입점·신뢰 경계·공용 자산의 실제 영향 경로를 분석한다.
수정 요청에서는 위험 코드를 고치고 회귀 검증과 독립 재검토까지 수행한다.
검토만 요청한 경우 읽기 전용을 유지한다. 실제 공유 서비스의 삭제·설정 변경·부하 테스트는
이번 작업이나 워크플로우의 기본 권한에 포함하지 않는다.

- base_branch: `main`
- work_branch: `feat/ch4570/add-security-scan` (기존 PR #13 유지)
- 작성 지침: workflow는 `skill-updater`, 실행 코드는 `code-authoring-router`와 해당 SQL 지침
- 기존 취약 평가 fixture는 탐지 회귀용으로 보존하며 운영 취약점 수정으로 가장하지 않는다.

## 구현 순서와 소유권

1. 평가 담당: 다양한 취약점과 공유 검색·객체·큐 리소스가 포함된 합성 fixture 및 불변 회귀
   테스트를 먼저 작성한다. 취약 baseline의 실패와 정상 대조군을 기록한다.
2. 주 담당: AUDIT/REMEDIATE 분기, 위협 유형별 coverage, 자산별 binding/권한/범위/예산 분석,
   수정 전·후 증거와 미해결 위험을 보존하는 워크플로우·KB·사용자 문서를 작성한다.
3. SQL 담당: 세미콜론 없는 SQL Server 제어문과 MySQL 제한 설정 실패를 오프라인 테스트로
   재현한 뒤 실행 전에 거부하도록 수정한다. 정상 조회와 연결 정리는 유지한다.
4. 평가 adapter 담당: 현재 CI의 62/63 기대값 불일치 수정, 같은 release의 지식과 실제
   읽기 전용 auditor를 연결하는 명시적 격리 profile을 구현·검증한다. 설정과 실행 증거를 구별한다.
5. 주 담당: DB 결과의 사후 절단만으로 막지 못하는 메모리/전송량 문제를 별도로 해결한다.
   행 수뿐 아니라 큰 셀, 취소 실패와 연결 재사용 경계를 포함한다.
6. 독립 보안 재검토, 실제 격리 behavioral trial, 설치·배포·회귀 게이트 후 PR을 갱신한다.

## 완료 증거

- 점검 범위에 인증·인가/테넌트, 비밀, 브라우저, SQL·명령 등 주입, SSRF, 파일/업로드,
  암호·세션, 의존성/설정, 자원 고갈과 공유 리소스 효과를 각각 근거와 함께 기록한다.
- 수정 요청의 산출물은 제안이 아니라 코드 diff와 결함을 잡는 테스트다. 테스트 약화,
  기능 삭제나 예외 무시로 통과하지 않는다.
- 공격/오류 경로는 민감 동작 전에 차단되고 정상 경로는 유지된다. 런타임 격리 미확인은
  미확인으로 남기며 공유 서비스에서 실행해 확인하지 않는다.
- 구조 검사, 설치, 모델 실행, 실제 서비스 검증을 구별한다. 미실행 단계가 있으면
  전체 완료를 주장하지 않는다. 현재 발견 사항은 구현 완료 증거가 아니다.
