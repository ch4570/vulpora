# 보안 점검·위험 제거 확장 계획

## 목표와 경계

예시 취약점 검색에 그치지 않고 진입점·신뢰 경계·공용 자산의 실제 영향 경로를 분석한다.
수정 요청에서는 위험 코드를 고치고 회귀 검증과 독립 재검토까지 수행한다.
검토만 요청한 경우 읽기 전용을 유지한다. 실제 공유 서비스의 삭제·설정 변경·부하 테스트는
이번 작업이나 워크플로우의 기본 권한에 포함하지 않는다.

- base_branch: `main`
- work_branch: `feat/ch4570/add-security-scan` (기존 PR #13 유지)
- 작성 지침: workflow는 `skill-updater`, 실행 코드는 `code-authoring-router`와 해당 SQL 지침
- 기존 취약 평가 fixture는 탐지 회귀용으로 보존하며 운영 취약점 수정으로 가장하지 않는다.

## 구현 순서와 소유권

1. 평가 담당: 다양한 취약점과 공유 검색·객체·큐 리소스가 포함된 합성 fixture 및 불변 회귀
   테스트를 먼저 작성한다. 취약 baseline의 실패와 정상 대조군을 기록한다.
2. 주 담당: AUDIT/REMEDIATE 분기, 위협 유형별 coverage, 자산별 binding/권한/범위/예산 분석,
   수정 전·후 증거와 미해결 위험을 보존하는 워크플로우·KB·사용자 문서를 작성한다.
3. SQL 담당: 세미콜론 없는 SQL Server 제어문과 MySQL 제한 설정 실패를 오프라인 테스트로
   재현한 뒤 실행 전에 거부하도록 수정한다. 정상 조회와 연결 정리는 유지한다.
4. 평가 adapter 담당: 현재 CI의 62/63 기대값 불일치 수정, 같은 release의 지식과 실제
   읽기 전용 auditor를 연결할 명시적 격리 profile을 준비·검증한다. 설정 생성, 실제
   auditor 실행, 호스트 격리 증거를 구별한다. 아래 CLI 미완료 항목을 완료로 처리하지 않는다.
5. 주 담당: DB 결과의 사후 절단만으로 막지 못하는 메모리/전송량 문제를 별도로 해결한다.
   행 수뿐 아니라 큰 셀, 취소 실패와 연결 재사용 경계를 포함한다.
6. 독립 보안 재검토, 실제 격리 behavioral trial, 설치·배포·회귀 게이트 후 PR을 갱신한다.

## 완료 증거

- 점검 범위에 인증·인가/테넌트, 비밀, 브라우저, SQL·명령 등 주입, SSRF, 파일/업로드,
  암호·세션, 의존성/설정, 자원 고갈과 공유 리소스 효과를 각각 근거와 함께 기록한다.
- 수정 요청의 산출물은 제안이 아니라 코드 diff와 결함을 잡는 테스트다. 테스트 약화,
  기능 삭제나 예외 무시로 통과하지 않는다.
- 공격/오류 경로는 민감 동작 전에 차단되고 정상 경로는 유지된다. 런타임 격리 미확인은
  미확인으로 남기며 공유 서비스에서 실행해 확인하지 않는다.
- 구조 검사, 설치, 모델 실행, 실제 서비스 검증을 구별한다. 필수 수정·회귀·독립 감사가
  미완료이면 해당 구현의 완료를 주장하지 않는다. 보류된 CLI 실행과 실제 서비스 검증을
  포함한 전체 실행 경로의 완료도 주장하지 않는다. 발견 사항만으로 수정 완료를 증명하지 않는다.

## 이번 PR의 완료 범위와 보류 항목

- 이번 구현의 완료 범위는 다양한 위험을 분석·수정하는 스킬 계약, 실제 SQL 위험 수정,
  검증되지 않은 평가 실행 차단, App native의 초기·최종 독립 감사 및 격리된 합성 소스
  수정 실험, 관련 회귀·설치·배포 검증이다.
- **CLI 자동 평가 transport와 그 격리 검증은 미완료/P2 보류**다. 같은 release의 자산과
  설정 생성은 검증했지만 CLI 0.154.0의 native child 생성 및 호스트 권한 검사가 실패했다.
  승인된 P2 공개 출판 방침을 유지하며, 이 항목을 완료하거나 전체 CLI 평가가 통과한 것으로
  바꾸지 않는다. 검증 가능한 런타임이 마련되면 별도로 재개해야 한다.
- App에서 실제 auditor를 실행한 증거는 CLI의 실행 증거를 대신하지 않는다. 현재 CLI에서는
  격리 플래그 제거·인증 복사로 우회하지 않고 실행을 차단한다. 실제 공유 서비스에 연결해
  이 한계를 확인하는 작업도 포함하지 않는다.

## 현재 검증 상태 (2026-09-10)

- SQL 실행 제한 우회: `86cd43d`에 SQL Server 제어문 차단과 MySQL 제한 설정 실패 시
  실행 거부를 반영했다. 당시 모듈 테스트 181개와 타입 검사를 통과했다.
- 점검·수정 워크플로우: `eaf5ab6`에 15개 위험 범주, 공유 자산의 실제 바인딩 확인,
  AUDIT/REMEDIATE 권한 분기와 수정 전·후 독립 감사를 반영했다. 합성 수정 실험은
  불변 테스트 67개를 통과했고, 주 담당의 별도 검증에서 sparse array 사례를 포함한
  강화 테스트 70개를 통과했다. 실제 공유 서비스는 사용하지 않았다.
- 평가 실행 경계: `3af3e8b`는 파일시스템 격리 확인에 실패하면 모델 실행 전에 중단한다.
  어댑터 테스트 19개를 통과했다. 현재 CLI의 격리 실패와 native child 실행 실패는
  확인된 한계이며, 설정 생성만으로 실제 격리·독립 감사 실행이 증명되지는 않는다.
- 결과 크기 우회: MSSQL의 `__proto__` 열 이름이 측정되지 않는 값을 보관하게 하는
  사례를 재현했다. 수정 전 관련 테스트 2개 실패, 수정 후 관련 테스트 20개 통과를
  구현 담당이 확인했고, 독립 읽기 전용 감사도 프로토타입 방어의 소스상 종결을 지지했다.
  프로토타입만의 검토를 전체 수신·취소 경로 검증으로 대체하지 않고 아래 통합 검증을 수행했다.
- 수신·수집 제한: 세 드라이버의 결과 수집 예산과 파서 진입 전 수신 한도를 통합했다.
  기본 수신 한도는 4 MiB이며 최대 32 MiB로 제한한다. 실제 라이브러리의 분할
  DataRow·MySQL 패킷·TDS/PLP 파서와 합성 TLS 배치 테스트 5개를 포함해, 동결된
  변경에서 주 담당이 전체 모듈 테스트 236개와 타입 검사를 별도로 통과했다.
  초과·취소 시 연결 폐기, 종료 오류에 대한 원래 제한 오류의 우선순위, 압축 우회
  거부와 정상 종료·롤백 후 원상 복구도 회귀 범위에 포함한다. 이 수신 한도는 이미
  할당된 OS/TLS 청크나 프로세스 RSS의 절대 상한을 뜻하지 않는다.
- 통합 독립 감사: 변경 파일 19개의 시작·종료 해시가 모두 동일한 범위에서
  `APPROVE_WITH_LIMITS`, 신규 확정 발견 0건을 받았다. 결과 수집·수신 제한과
  프로토타입 우회 차단의 종결을 지지하며, 위에 명시한 미검증 경계는 그대로 남긴다.
- PR #13에 SQL 변경 `99caf4f`까지 반영했다. 전체 오프라인 회귀를 포함한
  `npm run check`는 종료 코드 0으로 완료했고, `npm test`의 패키지 설치·제거 통합
  검사도 23/23 통과했다. 테스트용 디렉터리의 제거까지 별도로 확인했다. 이전 커밋의
  검사 결과를 재사용하지 않고 후속 소스 변경에 대해 새로 실행한 증거다. 구현 커밋
  `99caf4f`의 CI도 Ubuntu·macOS / Node 22·24에서 모두 통과했다.
- 마지막 변경은 위 완료 범위·CLI 보류 상태의 문서 정리와 포맷팅 주석 정정뿐이다.
  실행 토큰은 바뀌지 않았고, 주석 수정 후에도 모듈 테스트 236개와 타입 검사를 통과했다.
  문서의 App/CLI 완료 범위 구분도 독립 재검토를 통과했다. 배포 미리보기에서는 SQL
  변경 파일 19개가 모두 포함되고 저장소 상태·의존성 캐시가 제외됨을 확인했다.
  CLI 자동 평가의 미완료/P2 보류와 실제 서비스 검증의 제외 범위는 위 결정 기록대로 유지한다.
