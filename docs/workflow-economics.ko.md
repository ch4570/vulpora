# 작업에 맞는 workflow와 비용 확인

작업 하나를 **같은 완료 기준까지 끝내는 데 쓴 전체 비용**을 비교합니다. 짧은 프롬프트나 적은
첫 시도 토큰만으로 절감을 판단하지 않습니다. 실패·수리·검증용 모델 호출도 포함해야 합니다.

## 현재 사용할 수 있는 경로

| 작업 조건 | 기존 경로 | 비용 관리 원칙 |
|---|---|---|
| 범위·완료 조건·검증이 명확한 작은 수정 | `$start-task --lightweight` 또는 직접 실행 | 주 담당자 한 명, 관련 읽기 묶기, 필요한 검사 후 종료 |
| 기존 자격 조건을 만족하는 완결된 작은 편집 | 명시적 `edit-proposal` | 편집안 한 번과 결정적 검증; 4파일·4,096바이트 한도 유지 |
| 탐색이나 독립 전문 검토가 필요한 작업 | `$start-task --standard` | 결합된 작업은 한 명이 담당하고 독립성이 확인된 부분만 제한된 맥락으로 위임 |
| 보안·권한·비가역 작업 등 위험 하한 해당 | `$start-task --audit` | 기존 위험 하한과 필수 검증 유지; 비용 때문에 하향하지 않기 |

프로필을 지정해도 관측된 위험 조건은 우선합니다. `edit-proposal`은 자동 기본값이나 일반 작업
면제권이 아닙니다. 자격 조건과 실행 방법은 [편집안 계약](../evals/token-efficiency/PROPOSAL-EVAL.md)을 참고하세요.

## 복사할 수 있는 요청

```text
$start-task
목표: 검색 결과의 페이지 경계 중복을 수정한다.
범위: src/search.js, src/page.js, test/search.test.js.
제약: 기존 정렬·응답 형식 보존, 새 의존성·외부 쓰기 없음.
완료 조건: 빈 결과·동률 정렬·마지막 페이지 회귀를 통과하고 기존 동작이 유지됨.
검증: node --test test/search.test.js, 변경 diff 확인.
예산·중단: 최초 시도와 수리 1회. 사용량 불명·범위 밖 수정 필요 시 원인과 확인된 결과 보고.
```

일반 작업은 이 정도의 세션 brief면 충분합니다. 모든 작업에 JSON·DAG·상태 파일을 만들 필요는
없습니다. 도구 출력은 읽기 전에 필요한 범위로 제한하고, 수리에는 실패한 검사와 바뀐 소스를
중심으로 전달합니다. 새 변경·실패·근거가 없으면 관련 없는 통과 검사를 반복하지 않습니다.
모델의 품질 실패와 실행 환경 오류를 구분하며, 중단 조건을 성공으로 바꾸어 보고하지 않습니다.

## 구현된 기능과 새 검증의 구분

기존 프로필 선택·직접 실행·세션 공유 예산·제한된 편집안 실행은 이미 있습니다. 위 요청 양식은
그 기능의 사용 가이드이지 새 실행 모드가 아닙니다. 이번 추가는 [사전 고정 실험](../evals/token-efficiency/WORKFLOW-EVAL.md),
다중 파일 수정·테스트 작성·리뷰 채점기, 중복 없는 호출 비용 집계와 선택 실행 pilot입니다.
전역 workflow·모델·예산 기본값은 바꾸지 않습니다.

[첫 pilot](../evals/token-efficiency/results/workflow-pilot-2026-09-09.md)의 설정 오류 원본을 보존한 뒤,
[설정 호환성 수정 후 pilot](../evals/token-efficiency/results/workflow-pilot-configured-2026-09-09.md)를 실행했습니다.
3개 호출에서 645,777토큰을 관측했고 사전 토큰 한도로 나머지 6개 작업을 중단했습니다. 세 조건 모두
파일 범위 검사를 실패해 완료는 0건입니다. 완료당 비용·절감은 미확정이며 전역 기본값은 유지합니다.

비교에는 최초/최종 통과율, 회귀 결함 탐지, 실패·수리를 포함한 총토큰/검증된 완료 수,
비용 시나리오/검증된 완료 수, 지연시간을 함께 봅니다. 사용량이 누락되면 전체 비용은
`unknown`, 완료가 0건이면 완료당 비용은 정의되지 않습니다. 바이트를 청구 토큰으로 환산하지 않습니다.

개선·평가비는 운영 작업비와 분리합니다. `회수 작업 수 = 개선·평가비 / 작업당 절감액`은
양쪽 계측 범위가 같고 절감액이 보수적 비용 구간에서도 양수일 때만 계산합니다.
실제 청구 증거가 없으면 API 환산액으로 실제 청구 절감이나 투자비 회수를 주장하지 않습니다.

품질이 낮아지거나 비용 구간이 겹치거나 표본·계측이 부족하면 채택을 보류합니다. 과거 편집안
실험의 83.6%는 작은 합성 과제 결과이며 일반 저장소 작업의 절감 보장이 아닙니다.
운영 runner·서명·제공자 강제 과금 한도는 별도 [#1](https://github.com/ch4570/vulpora/issues/1) 범위입니다.

## 2026-09-11 공개 검토 정정: patch 보존 범위

사전 규약의 “모든 시도의 patch 보존” 문장과 실행기의 보존 설명은 실제 안전 필터보다 넓게 쓰였습니다.
실행기는 변경 범위·일반 파일·Git HEAD 보존 검사를 통과한 경우에만 patch를 저장합니다.
설정 수정 후 pilot의 세 시도는 범위 검사를 실패했으므로 patch를 내보내지 않았습니다.
이는 사전 규약과 실제 산출물의 차이이며, 사후에 규약을 충족한 것으로 해석하지 않습니다.

원본 규약·실행기·결과 JSON은 바꾸지 않고 이 정정을 별도로 남깁니다. 카운터·실패 판정·변경 경로는
보존됐지만 거부된 patch와 raw 대화는 없습니다. 다음 실험은 안전하게 내보낼 수 있는 산출물의 범위를
새 규약에서 먼저 고정해야 합니다. 이번 공개 검토에서는 유료 pilot를 다시 실행하지 않았습니다.
