1. 이 작업의 한 줄 요약

이번 변경은 vulpora을 "에이전트가 무슨 답을 했는가"만 보는 구조에서 "답을 만들기 위해 어떻게 행동했는가"까지 기록하고 평가할 수 있는 구조로 확장한 작업입니다.

기존 behavioral eval은 주로 최종 답변 텍스트가 기대 조건을 만족하는지를 확인했습니다. 하지만 개발용 에이전트는 답변만 맞으면 충분하지 않습니다. 어떤 파일을 읽었는지, 불필요한 명령을 많이 실행했는지, 위험한 행동을 시도했는지, 비용을 과하게 썼는지도 품질의 일부입니다.

2. 왜 이게 필요한가

기존 평가의 약점

  • 최종 답변 텍스트가 그럴듯하면 통과하기 쉽습니다.
  • 실행 과정이 비효율적이거나 위험해도 점수에 반영하기 어렵습니다.
  • Claude Code, Codex, OpenCode 같은 런타임을 같은 기준으로 비교하기 어렵습니다.
  • 에이전트 설계를 바꿨을 때 진짜 좋아졌는지 회귀 테스트하기 어렵습니다.

이번 변경이 여는 가능성

  • 최종 결과, 실행 과정, 안전성, 비용을 같은 결과 파일에 기록할 수 있습니다.
  • 런타임별 adapter만 붙이면 동일한 behavioral case를 반복 실행할 수 있습니다.
  • 에이전트 프롬프트나 skill bundle 변경 전후를 비교할 수 있습니다.
  • 나중에 agent design methodology를 점수 기반으로 검증할 수 있습니다.

3. 평가 기준의 변화

기존 관점은 아래에 가까웠습니다.

최종 답변이 기대 키워드와 산출물을 포함했는가?

이번 작업 이후 목표 구조는 아래와 같습니다.

평가 축 결과 필드 의미 예시
결과 품질 outcome_score 최종 답변이 기대 조건을 만족했는지 필수 키워드, 필수 artifact, 금지 패턴 검사
과정 품질 process_score 실행 과정이 적절하고 과도하지 않았는지 툴 호출, 파일 읽기, 파일 쓰기, 명령 실행 수
안전성 safety_score 금지 행동이나 guardrail 위반이 있었는지 forbidden action, guardrail trip
비용/효율 cost_score 시간, 명령 수, token 사용량이 과도하지 않았는지 elapsed seconds, estimated tokens, command count

4. 새 실행 흐름

1. Case 로드 behavioral case YAML에서 prompt, fixture, threshold를 읽습니다.
2. Adapter 실행 Claude Code, Codex, OpenCode 등 런타임 adapter가 최종 답변을 stdout으로 출력합니다.
3. Metrics 기록 adapter가 VULPORA_METRICS_FILE에 실행 메트릭을 남깁니다.
4. Grader 평가 텍스트 grader와 metrics sidecar grader가 각각 결과와 과정을 평가합니다.
5. YAML 저장 outcome, process, safety, cost 점수를 하나의 결과 파일로 저장합니다.

5. 변경된 파일

파일 변경 내용 의미
evals/behavioral/run-behavioral-evals.sh adapter 실행 시 metrics sidecar 경로를 전달하고, 결과 YAML에 process/safety/cost 필드를 기록하도록 확장했습니다. 평가 runner의 핵심 배관입니다.
evals/behavioral/graders/metrics-sidecar.sh sidecar 파일을 읽어 process, safety, cost 점수와 failure signal을 계산하는 새 grader를 추가했습니다. 실행 과정 평가의 시작점입니다.
evals/behavioral/adapters/README.md 런타임 adapter가 지켜야 하는 환경 변수, stdout, stderr, metrics sidecar 계약을 문서화했습니다. Claude Code, Codex, OpenCode adapter를 붙이기 위한 명세입니다.
evals/behavioral/adapters/sample-adapter.sh LLM을 호출하지 않고 평가 배관만 검증하는 샘플 adapter를 추가했습니다. 실제 adapter 구현 전 runner가 제대로 동작하는지 확인할 수 있습니다.
evals/behavioral/README.md 새 adapter 계약, sidecar 예시, 결과 스키마, 현재 한계를 반영했습니다. 평가 시스템 사용자를 위한 운영 문서입니다.
STANDARD.md behavioral eval 표준에 metrics sidecar 규칙을 추가했습니다. 앞으로 vulpora에 들어오는 에이전트가 따라야 할 기준입니다.
README.md 현재 agent, bundle, skill 수와 behavioral eval 상태를 최신화했습니다. 저장소 첫 화면의 설명을 현재 구현 상태와 맞췄습니다.

6. Metrics sidecar 계약

adapter는 실행 중 관측한 값을 아래처럼 VULPORA_METRICS_FILE에 기록할 수 있습니다. 현재 구현은 flat YAML 또는 단순 JSON에 가까운 key-value 형식을 읽습니다. 

elapsed_seconds: 12
tool_calls: 8
files_read: 15
files_written: 2
command_count: 4
estimated_tokens: 4200
forbidden_action_hits: 0
guardrail_trips: 0

이 값은 아직 정교한 trace 분석이 아닙니다. 지금 단계에서는 런타임 adapter가 제공하는 얕은 관측값을 같은 스키마에 담는 것이 목적입니다.

7. 결과 YAML 예시

sample adapter를 실행하면 결과 파일에 아래와 같은 구조가 저장됩니다.

expected: { outcome_threshold: 0.8, process_threshold: 0.7, safety_threshold: 1.0 }
actual: { outcome_score: 1.000, process_score: 1.000, safety_score: 1.000, cost_score: 1.000 }
metrics:
  outcome_score: 1.000
  process_score: 1.000
  safety_score: 1.000
  cost_score: 1.000
  elapsed_seconds: 1
  tool_calls: 2
  files_read: 1
  files_written: 0
  command_count: 0
  estimated_tokens: 256
  forbidden_action_hits: 0
  guardrail_trips: 0
behavioral:
  runtime: claude-code
  baseline_mode: plain-runtime
  artifact_hash: sha256:...
  metrics_sidecar: present
  process_score: 1.000
  safety_score: 1.000
  cost_score: 1.000

9. 현재 상태와 한계

완료된 것

  • behavioral runner가 metrics sidecar를 받을 수 있습니다.
  • 결과 YAML에 outcome/process/safety/cost 점수가 같이 저장됩니다.
  • adapter contract가 문서화되었습니다.
  • sample adapter로 전체 배관을 검증했습니다.
  • local Claude Code adapter 골격을 추가했습니다.
  • baseline matrix 실행기와 Markdown 결과 리포터를 추가했습니다.
  • README와 STANDARD 문서를 현재 구조에 맞게 업데이트했습니다.

아직 남은 것

  • 설치된 Claude Code CLI의 stream-json 형식에 맞춘 local adapter 보정
  • 실제 Codex adapter 구현
  • OpenCode adapter 구현
  • baseline matrix 결과의 regression 판정 자동화
  • trace 기반의 정교한 process/safety/cost 산식
  • 여러 case 결과를 묶은 HTML 리포트 자동 생성
주의: 이번 작업은 완성된 에이전트 벤치마크가 아니라, 실제 벤치마크를 만들기 위한 runtime metrics 배관입니다. 지금의 process/cost 점수는 휴리스틱이며, 실제 런타임 adapter가 더 풍부한 trace를 제공할수록 정교해질 수 있습니다.

10. Claude에게 이어서 시킬 작업

이 브랜치를 받은 Claude에게는 아래 지시를 주면 됩니다.

현재 브랜치 feat/behavioral-eval-runtime-metrics에서 변경사항을 리뷰하고 테스트해줘.

확인할 것:
1. behavioral runner가 VULPORA_METRICS_FILE을 안전하게 넘기는지
2. metrics-sidecar.sh가 sidecar 없음, 정상 sidecar, forbidden action case를 모두 잘 처리하는지
3. 결과 YAML schema가 기존 eval 소비자와 충돌하지 않는지
4. sample-adapter.sh가 adapter contract 예시로 충분한지
5. claude-code-local-adapter.sh가 로컬 Claude Code stream-json을 올바르게 파싱하는지
6. run-baseline-matrix.sh와 report-results.sh가 baseline 결과를 안정적으로 다루는지
7. README, STANDARD, evals/behavioral/README.md가 실제 동작과 일치하는지

11. 다음 단계 제안

  1. Claude Code adapter 보정: 실제 설치된 Claude Code CLI의 stream-json 스키마를 기준으로 최종 응답과 tool metrics 파싱을 확정합니다.
  2. Codex adapter 구현: 동일한 behavioral case를 Codex로 실행하고 결과를 같은 스키마에 저장합니다.
  3. Baseline regression 판정: plain-runtime, agent-only, agent-memory 결과를 비교해 하락을 자동 탐지합니다.
  4. 리포트 고도화: Markdown 요약을 HTML 비교 리포트와 PR/로컬 리뷰용 요약으로 발전시킵니다.
  5. 점수 산식 정교화: 단순 카운트 기반에서 trace event 기반 평가로 발전시킵니다.

12. 최종 판단

이번 변경의 가치는 "당장 모든 에이전트를 완벽하게 평가한다"가 아닙니다. 핵심은 앞으로 다양한 agent, skill, runtime을 같은 평가 언어로 비교할 수 있는 기반을 만든 것입니다.

정리하면: vulpora은 이제 에이전트 카탈로그에서 에이전트 실험실로 넘어가기 위한 첫 번째 평가 인프라를 갖췄습니다. 다음 작업은 local Claude adapter를 실제 설치 환경에 맞게 보정하고, baseline 비교 결과를 regression 판정으로 연결하는 것입니다.
