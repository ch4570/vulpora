# KB: 편집 표면과 컴포넌트 선택

> 근거: harness2의 편집 계약(`core/tree.py`: 바꾼 것만 내고 나머지는 상속)과 INV·DOM 제안
> 템플릿(`core/prompts.py`). vulpora 자산 구조(STANDARD.md)에 맞게 옮겼다.

## 1. 편집 표면

- 대상은 지정한 자산 경로 아래 텍스트 파일뿐이다: 진입 파일(SKILL.md 또는 에이전트 정의),
  SOUL.md, `reference/principles.md`, `reference/kb/*.md`, `scripts/*`.
- **생략=상속**: 후보는 바꾸거나 추가하는 파일만 낸다. 나머지는 부모(원본 또는 직전 체크포인트)에서 온다.
- 진입 파일은 삭제할 수 없고 frontmatter `name`은 바꿀 수 없다. 새 KB 토픽은 `title`·`source`와
  체크리스트 절을 갖춰야 한다.

## 2. INV와 DOM

| 차원 | 맡는 것 | 맡지 않는 것 |
|---|---|---|
| INV | 절차, 도구 오류 대응, 순서, 완료 확인, 반복 작업 자동화 | 분야 규칙, 필수 절, 자료의 사실 |
| DOM | 산출물 계약, 분석 동작, 판단 규칙, 전문가가 잡는 누락 | 명령, 재시도, 읽는 순서, 스크립트 |

## 3. 컴포넌트 고르기 (싼 것부터)

1. 한 문장으로 고쳐지는 순서 문제 → 진입 파일의 짧은 문장.
2. 계기가 분명한 다단계 절차나 지식 → 필요할 때 읽히는 reference/KB 토픽, 진입 파일에서 이름으로 가리킨다.
3. 반복되는 결정적 추출·변환·검사 → `scripts/`의 스크립트, 입력·출력·실패 동작을 명시한다.
4. 도구 오류 → 원인 분류(입력 오류, 시간 초과, 능력 부족, 권한, 출력 미확인)와 한 번의 대안, 멈출 조건.

진입 파일이 30% 넘게 커지면 검증에서 거절된다. 상황별 지식은 KB로 옮긴다.

## 리뷰 훅 (점검 체크리스트)

- [ ] 후보가 바꾼 파일만 담고, 편집 표면 밖 경로를 건드리지 않았는가?
- [ ] INV 후보에 분야 규칙이, DOM 후보에 절차 변경이 섞이지 않았는가?
- [ ] 진입 파일에 더한 만큼 뺐거나, 상황별 지식을 KB로 옮겼는가?
- [ ] 이번 과제의 사실을 장기 지식처럼 적지 않았는가?
- [ ] 출처 없는 표준·식별자·인용을 만들어 넣지 않았는가?
