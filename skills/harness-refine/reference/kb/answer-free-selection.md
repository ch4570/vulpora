# KB: 정답 없는 익명 선택

> 근거: Harness² 선택 단계(`core/selection.py`의 익명 ID·셔플, `core/prompts.py`의 선택 기준)와
> 채점 정보 유출 차단(`core/context.py`의 grader-verdict tripwire).

## 1. 왜 정답 없이 고르는가

- 실제 사용 환경에는 채점 기준이 없다. 정제 루프가 채점 기준에 맞추면 기준에 과적합하고 일반화가 깨진다.
- 그래서 제안·합성·선택 어디에도 기대 결과·통과 기준·점수를 넣지 않는다. behavioral case에서 가져올
  때도 `prompt`, `fixture_repo`, 안전 제약만 남긴다.
- 채점 어휘(`must_find`, `pass_threshold`, `outcome_score` 등)가 과제·실행 증거·회고에 보이거나 후보가
  새로 더하면 스크립트가 거절한다. 원본 하네스가 평가 문서를 다루느라 언급하는 경우는 경고로만 남긴다.
  이것은 경계 감지기이지 방어 전부가 아니다. 걸리면 그 정보가 들어온 경로를 찾아 막는다.

## 2. 익명 풀

- 풀에는 원본 하네스의 산출물도 들어간다. 원본을 고르는 것은 정상적인 결론(KEEP_BASE)이다.
- ID는 실행마다 고정된 시드로 섞는다. 같은 실행에서는 재현되고, 선택자에게는 아무 정보도 주지 않는다.
- 대응표(`.pool-key.json`)는 풀 디렉터리 밖에 둔다. 선택자에게는 풀과 원자료만 준다.

## 3. 선택 기준 순서

전달(요청한 산출물과 부분이 모두 있는가) → 형식 준수(요청하지 않은 추가·개명·재배열 없음) →
원자료 충실도(주장 대조, 지어낸 구체값 거절) → 내부 일관성 → 실사용 적합성 → 마감(자리표시자 없음).
길이와 다듬새는 장점이 아니다.

## 리뷰 훅 (점검 체크리스트)

- [ ] 선택자 입력에 라벨·하네스·궤적·채점 기준이 빠져 있는가?
- [ ] 풀에 원본 산출물이 포함됐는가? 빠졌다면 그 이유를 보고했는가?
- [ ] 선택 근거가 결정 기준과 차점 후보의 결함을 짚는가?
- [ ] 채점은 선택이 끝난 뒤 회귀 검증에서만 썼는가?
