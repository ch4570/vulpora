# KB: 하네스 변경 안전 제안 (proposing changes safely)

> 외부 트렌드를 현재 하네스에 반영할 때의 닫힌 루프: **리서치 → 중복제거 → 점수화 →
> 가역적 적용안 → 승인**. 이 스킬(`harness-propose`) 자신의 절차를 그대로 미러링한다.
> 근거: Anthropic "Building effective agents"(단순함 우선·human-in-the-loop·가드레일).

## 1. 트렌드 리서치

- 하네스 엔지니어링/에이전트/컨텍스트 엔지니어링/멀티에이전트 관련 **신규 공개물**을 수집한다.
- 각 항목을 `{제목, URL, 발행일, 1줄 요약, 핵심 주장 3~5}`로 정규화한다.
- 소스군별(벤더 엔지니어링 블로그·논문·실무 블로그)로 병렬 위임 가능하되, **판단은 위임 금지**.

## 2. 중복 제거(dedup)

- 현재 하네스가 **이미 가진 기능/지식과 겹치면 기각**한다(완전 중복 채택 금지).
- 직전 회차의 보류/기각 기록(예: `watch.md`)과 대조해 재제안을 막는다.

## 3. 점수화: Fit / Novelty / ROI / Risk

| 축 | 기준 |
|---|---|
| **Fit** | 프로젝트 스택·아키텍처 적합성(주 언어/프레임워크·서빙 계층·모듈 구성) (high/med/low) |
| **Novelty** | 현재 하네스와의 중복도 (new / partial / full-dup) |
| **ROI** | 품질 이득 대비 구현 비용 (high/med/low) |
| **Risk** | 모델 독립성 훼손·기존 규약 충돌·보안 (high/med/low) |

- 버킷: **채택**(Fit≥med, Novelty≠full, ROI≥med, Risk≤med) · **보류** · **기각**.

## 4. 가역적 적용안(apply-spec)

채택 항목마다 다음을 명세한다.
```
제목
└─ 대상: <보강할 파일/신규> (또는 docs/...)
└─ 변경 유형: [지식 추가 | 스킬 추가·수정 | 에이전트 추가·수정 | 규칙 추가 | 문서]
└─ 변경 요지: (≤3줄)
└─ 검증: (예: 코드 리뷰, 특정 모듈 테스트, 수동 확인)
└─ 롤백: (단일 커밋 revert 가능 여부)
```

## 5. 승인 게이트(STOP)

- 새 제안서 작성과 기존 하네스 적용 권한을 구분한다. 제안 요청만으로 기존 정책·보고서를 바꾸지 않는다.
- 아직 승인되지 않은 적용안은 사용자에게 결정받는다. 같은 세션에서 이미 승인한 항목과 범위는 다시 묻지 않는다.
- 기각 항목은 다음 회차 중복 방지를 위해 기록으로 남긴다.

## 6. 모델 독립성

- 제안·적용안에 **특정 모델 버전을 하드코딩하지 않는다.** 모든 모델에서 성립할 규칙으로 쓴다.

## 리뷰 훅
- [ ] 수집 항목이 `{제목,URL,발행일,요약,핵심주장}`으로 정규화됐는가.
- [ ] **현재 하네스/직전 기각**과 대조해 중복을 걸렀는가.
- [ ] 각 항목이 **Fit/Novelty/ROI/Risk** 4축으로 점수화됐는가.
- [ ] 채택 항목마다 **가역적 적용안(검증·롤백 포함)**이 있는가.
- [ ] **승인 전 하네스 미수정** 원칙을 지키는가.
- [ ] 제안에 **특정 모델 버전이 하드코딩되지 않았는가**.
