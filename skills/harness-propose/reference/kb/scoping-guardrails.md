# KB: 스코핑 & 가드레일 (scoping & guardrails)

> 에이전트의 권한 범위를 좁히고 비가역/고영향 행동을 통제하는 규칙.
> 근거: Anthropic "Building effective agents"(human-in-the-loop, guardrails).

## 1. 기본이 안전(safe by default)

- 비가역·고영향 행위(파일 수정·배포·삭제·외부 쓰기)는 **기본값을 "제안만"**으로 둔다.
- 자율 실행은 예외이며, 명시적으로 허용된 좁은 범위에서만 한다.

## 2. 승인 게이트(approval gate)

- 고영향 행동 전에 **사람 승인**을 받는다(human-in-the-loop).
- 승인 단위는 **개별 변경**으로 쪼갠다("모두 승인 / 1,3만 승인 / 전부 보류"처럼 선택 가능하게).
- 승인되지 않은 기존 대상 파일은 수정하지 않는다. 제안 요청은 새 제안서 작성 권한이며,
  같은 세션의 명시적 적용 승인은 유지한다. 누락된 정책·보고서를 선행 조건으로 만들어 내지 않는다.

## 3. MUST / MUST NOT 하드 규칙

- 모델이 추론으로 메우게 두지 말고 금지선을 **명문 규칙**으로 건다.
- 보호 대상 경로(설정·정책·문서 등)와 허용 작업을 명시한다.
- 규칙은 모델 버전과 무관하게 성립하도록 쓴다(모델 독립성).

## 4. blast-radius 제한

- **변경 대상·경로·건수**에 상한을 둔다(예: 한 번에 N개 파일/행 이하).
- 광범위 영향 작업은 단계로 쪼개 점진 적용한다.
- 외부 호출·쓰기에는 범위(스코프)·레이트 제한을 둔다.

## 5. dry-run / preview

- 적용 전 **무엇이 바뀌는지 미리보기**(diff·영향 목록)를 제시한다.
- 미리보기와 실제 적용을 별도 단계로 분리한다.

## 6. 가역성 / 롤백(reversibility)

- 모든 변경은 **되돌릴 방법**을 동반한다(단일 커밋 revert 등).
- 되돌릴 수 없는 작업은 **더 강한 승인**과 명시적 경고를 요구한다.
- 롤백 절차를 적용안에 함께 기록한다(→ `proposing-changes-safely.md`).

## 리뷰 훅
- [ ] 비가역·고영향 행동의 기본값이 **"제안만"**인가.
- [ ] 고영향 변경 전 **사람 승인 게이트**가 있는가(개별 선택 가능).
- [ ] **MUST NOT 보호 경로/금지선**이 명문화돼 있는가.
- [ ] 변경 **대상/건수에 상한(blast-radius)**이 있는가.
- [ ] 적용 전 **dry-run/preview**를 제시하는가.
- [ ] 각 변경에 **롤백 방법**이 정의돼 있는가.
- [ ] 규칙이 **특정 모델 버전에 의존하지 않는가**.
