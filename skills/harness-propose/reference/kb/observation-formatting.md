# KB: 관측/결과 포맷팅 (observation formatting)

> 도구 결과(관측)를 모델에 어떻게 넣느냐가 컨텍스트 예산과 판단 품질을 좌우한다.
> 근거: Anthropic "Effective context engineering for AI agents".

## 1. 토큰 경제: 컨텍스트는 유한 자원

- 관측은 모델 컨텍스트를 직접 소비한다. **길수록 좋은 게 아니라, 의사결정에 필요한 신호만** 남긴다.
- 한 번에 모든 것을 넣지 말고 **필요할 때 가져오는(retrieve-on-demand)** 형태로 분할한다.
- 컨텍스트가 길어질수록 핵심 신호가 묻히는 **context rot**가 생긴다. 분량 자체를 비용으로 본다.

## 2. 잘림(truncation) 전략

- 무작정 앞부분만 자르지 않는다. **핵심 보존 후 미루기**:
  - 에러·요약·핵심 행은 보존.
  - 대량 본문은 페이지네이션(`offset/limit`)·요약·요청형 조회로 미룬다.
- 잘렸음을 모델에 **명시**한다("총 1,240행 중 1~50행, 더 보려면 offset 사용").

## 3. 신호 vs 잡음

- 반복되는 보일러플레이트(헤더·장식·중복 메타)는 제거한다.
- 가장 결정적인 정보(실패 원인, 변경 영향, 다음 액션 후보)를 **상단**에 둔다.

## 4. 구조 vs 산문

| 결과 성격 | 권장 포맷 |
|---|---|
| 기계가 파싱/집계할 데이터 | 표·JSON 유사 구조 |
| 판단을 요하는 맥락 | 간결한 산문 |
| 목록·다건 | 핵심 필드만 추린 행 단위 |

- 둘을 섞어 장황하게 만들지 않는다. 구조화된 결과에 군더더기 설명을 덧붙이지 않는다.

## 5. 실패를 드러낸다

- 빈 결과·조용한 실패는 모델을 헛돌게 한다. **실패 신호를 관측 최상단에** 명시한다.
- "결과 없음"과 "오류로 못 가져옴"을 구분한다(원인이 다르므로 다음 행동도 다르다).

## 리뷰 훅
- [ ] 관측이 **의사결정에 필요한 신호만** 담는가(불필요한 분량 제거).
- [ ] 대량 결과를 **페이지네이션/요약/요청형**으로 분할하는가.
- [ ] 잘림이 발생하면 **잘렸음과 더 보는 법**을 표시하는가.
- [ ] 결정적 정보가 **상단**에 오는가.
- [ ] 데이터는 구조화, 맥락은 산문으로 **포맷이 적절히 분리**되는가.
- [ ] **빈 결과 vs 오류**가 구분돼 드러나는가.
