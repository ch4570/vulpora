# KB: 액션 스페이스 설계 (action space design)

> 에이전트가 환경에 작용하는 **행동의 집합**(도구 묶음)을 어떻게 구성하느냐가 완성률을 좌우한다.
> 근거: Anthropic "Building effective agents", "Writing effective tools for agents".

## 1. 최소·직교(minimal & orthogonal)

- **도구 수를 늘리는 것이 능력을 늘리는 게 아니다.** 후보 도구가 많을수록 모델의 선택 부담과
  오선택 확률이 커진다. 한 의도 → 한 도구로 매핑한다.
- **직교성**: 도구들의 기능이 서로 겹치지 않게 한다. 두 도구가 같은 일을 다르게 하면 모델은
  무작위로 고르고, 실패 시 어느 쪽을 고쳐야 할지 모호해진다.
- 새 도구를 추가하기 전에 **기존 도구의 파라미터 확장으로 풀 수 있는지** 먼저 본다.

## 2. 겹치거나 모호한 도구 제거

| 안티패턴 | 문제 | 교정 |
|---|---|---|
| `getUser` + `fetchUser` + `loadUser` | 동의어 도구 난립 | 하나로 통합 |
| 만능 `run(command)` 단일 도구 | blast-radius 과대·오용 쉬움 | 의도별 좁은 도구로 분해 |
| `search`와 `query`가 구분 안 됨 | 선택 모호 | 설명으로 사용 시점 분리 |

## 3. 에러 메시지 = 피드백 채널

- 실패를 **모델이 다음 행동을 교정할 수 있는 형태**로 돌려준다. 단순 stack trace보다
  "무엇이/왜/어떻게 고치나"를 구조화한다.
- 잘못된 파라미터는 **허용값·예시**를 함께 알려준다(예: "status는 OPEN|CLOSED 중 하나").
- 부분 성공은 성공/실패를 명확히 분리해 보고한다.

## 4. 멱등성(idempotency)과 안전 재시도

- 같은 입력으로 재호출해도 결과·부작용이 동일하도록 설계하면 루프 재시도가 안전해진다.
- 생성 계열 도구는 **자연 키/idempotency key**로 중복 생성을 막는다.
- 비가역 행동은 별도 승인 게이트 뒤로 보낸다(→ `scoping-guardrails.md`).

## 5. 단순함 우선

- 액션 스페이스를 키우기 전에 **에이전트가 정말 필요한지** 자문한다. 단발 호출/검색 증강으로
  풀리면 도구 루프를 만들지 않는다.

## 리뷰 훅
- [ ] 같은 일을 하는 **중복·동의어 도구**가 없는가.
- [ ] 각 도구가 **단일 책임**을 갖고 의도와 1:1로 매핑되는가.
- [ ] 만능/임의실행 도구가 꼭 필요한가, 좁은 도구로 분해 가능한가.
- [ ] 실패가 **교정 가능한 구조화 에러**로 돌아오는가(허용값·예시 포함).
- [ ] 재시도/중복 호출이 **멱등**하거나 idempotency key로 보호되는가.
- [ ] 새 도구 대신 **기존 도구 확장**으로 풀 수 있는지 검토했는가.
