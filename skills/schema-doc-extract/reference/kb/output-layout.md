# KB: 산출 레이아웃 + 테이블 명세 포맷

> 이 KB는 공식 외부 표준이 아니라 **Vulpora 내부 산출물 규약**이다. 프로젝트에 기존 관례가 있으면 그것이 우선한다.
> 목적: ERD/명세 산출물을 **결정적·멱등·diff 가능**하게 고정하는 것.

## 1. 기본 디렉터리 레이아웃 — 테이블 명세는 스키마별 분리
```text
docs/schema/
├── erd.md              # Mermaid erDiagram 블록(전체 ERD — 모든 스키마/cross-schema 관계)
└── tables/
    ├── _index.md       # 스키마 인덱스(스키마 → 테이블 수·링크) + 전역 drift 요약
    ├── public.md       # public 스키마 명세 + 해당 스키마 Drift 섹션
    └── <schema>.md     # 스키마당 1파일 (스키마명 사전순)
```
- **테이블 명세는 스키마당 파일 하나**(`tables/<schema>.md`)로 분리한다. 단일 `tables.md`에 전 스키마를 몰지 않는다 — diff 범위가 해당 스키마로 한정되고 탐색·소유권이 명확해진다.
- 단일 스키마(`public`만)여도 `tables/public.md`로 쓴다(디렉터리 형태 유지 — 결정론·확장성). 레거시 `tables.md`는 분리 후 제거(또는 `_index.md` 포인터만).
- 파일명은 스키마명(소문자 식별자). 식별자로 못 쓰는 문자는 `_`로 치환하고 `_index.md`에 원래 이름 병기.
- **ERD는 단일 유지**: 관계가 스키마 경계를 넘으므로 `erd.md` 하나로 둔다(스키마별 ERD로 쪼개지 않음).
- 프로젝트가 이미 `docs/erd/` 등 다른 루트를 쓰면 그 루트를 따르되, `tables/<schema>.md` 분리 규칙은 동일 적용. 그 외 기본은 `docs/schema/`.
- 모든 파일 상단에 생성 출처 한 줄(입력: Flyway 마이그레이션 + 엔티티 코드, 정적)을 둔다.

## 2. 테이블 명세 컬럼 포맷 (고정)
각 테이블은 `<스키마>.<테이블> — <논리설명>` 헤더 + 다음 6열 표.

| 컬럼 | 타입 | NULL | 기본값 | 키 | 설명 |
|------|------|------|--------|----|------|
| order_id | bigint | NO | nextval | PK | 주문 식별자 |
| member_id | bigint | NO |  | FK | 주문한 회원 |
| status | varchar(50) | NO | 'PENDING' |  | 주문 상태 |

- **타입**: 마이그레이션 물리 타입 그대로(`varchar(50)`, `numeric(12,2)`, `timestamptz`).
- **NULL**: `NO`/`YES`(NOT NULL이면 `NO`).
- **기본값**: SQL `DEFAULT` 값. 없으면 빈칸. 실데이터·시드 값은 넣지 않는다.
- **키**: `PK`/`FK`/`UK` 조합. enum 컬럼은 설명에 허용 값을 병기(`상태: PENDING|PAID|...`).

## 3. 테이블별 하위 섹션
표 아래에 불릿으로 둔다(있을 때만, 순서 고정):
- **인덱스**: `이름 (컬럼들) [UNIQUE|PARTIAL ...]`.
- **제약**: PK/UNIQUE/CHECK/FK 제약을 이름과 함께.
- **관계**: `이 테이블 N — 1 상대 (FK컬럼 → 상대.PK)` 형태로 카디널리티 명시.

## 4. Drift 섹션 (스키마 파일마다 항상 존재)
- 각 `tables/<schema>.md` 끝에 그 **스키마 테이블 한정** 코드 ↔ 마이그레이션 불일치를 모은다.
- 불일치가 없으면 **"검출된 drift 없음"** 을 명시한다(섹션 자체는 항상 둔다).
- `tables/_index.md`에는 **전역 drift 요약(스키마별 건수)** 만 둔다 — 상세는 각 스키마 파일.

## 5. diff 안정성을 위한 정렬 규칙
- **스키마 파일/인덱스 항목**: 스키마명 **알파벳 오름차순**(`_index.md`의 표·파일 생성 순서 모두).
- **파일 내 테이블**: 테이블명 **알파벳 오름차순**.
- **컬럼**: 마이그레이션 **선언 순서** 유지(알파벳 정렬 아님 — 물리 순서가 의미를 가짐).
- **인덱스/제약**: 이름 알파벳순.
- 동일 입력이면 동일 바이트 산출이 목표. 타임스탬프·랜덤·절대경로 같은 비결정 요소를 본문에 넣지 않는다.

## 리뷰 훅
- [ ] 테이블 명세가 **스키마당 파일 하나**(`docs/schema/tables/<schema>.md`)로 분리됐고, 한 파일에 다른 스키마 테이블이 섞이지 않았는가.
- [ ] `docs/schema/tables/_index.md`가 존재하고 모든 스키마 파일을 사전순으로 링크하며 테이블 수가 실제와 일치하는가.
- [ ] ERD는 `docs/schema/erd.md` 단일이며(또는 프로젝트 기존 관례), 레거시 단일 `tables.md`를 남기지 않았는가.
- [ ] 명세 표가 `컬럼|타입|NULL|기본값|키|설명` 6열을 정확히 따르는가.
- [ ] 타입은 마이그레이션 물리 타입 그대로이고, 실데이터·시드 값이 새지 않았는가.
- [ ] 인덱스/제약/관계 하위 섹션 순서가 고정돼 있는가.
- [ ] **각 스키마 파일에 Drift 섹션이 존재**하는가(없으면 "검출된 drift 없음").
- [ ] 스키마 파일은 스키마명 사전순, 파일 내 테이블은 이름 사전순, 컬럼은 선언 순서로 정렬돼 재실행 시 diff가 안정적인가.
