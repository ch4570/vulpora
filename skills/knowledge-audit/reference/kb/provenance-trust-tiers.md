# KB: 출처(provenance)와 신뢰 등급

## 1. 신뢰 등급 (trust tier)

지식 항목은 **출처와 검증 상태**에 따라 3등급으로 나눈다. 등급이 곧 인용 가능성·우선순위다.

| 등급 | 정의 | 인용 가능 | 비고 |
|------|------|-----------|------|
| **정본(curated/verified)** | 사람 또는 코드 실증으로 검증됨. 정본 KB에 편입됨 | 예 | 단일 출처(SSOT). 다른 항목이 이걸 가리킨다 |
| **auto(machine-written)** | 에이전트가 자동 기록. 미검증 | 조건부 | 승급 전까지 **근거로 인용 금지** |
| **unverified(미검증)** | 출처 불명·근거 부재·검증 불가 | 아니오 | 보류 또는 폐기 대상 |

> **규칙**: 미검증/auto 항목을 다른 판단의 **근거로 인용하지 않는다.** 검증된 정본만 인용 가능.

## 2. provenance(출처) 기록 — 무엇을 남기는가

W3C PROV-O는 출처를 세 핵심 요소로 모델링한다. KB 항목도 동일하게 기록한다.

| PROV-O 개념 | KB에서의 의미 | 기록 필드 |
|-------------|---------------|-----------|
| **Entity** | 지식 항목 자체 | 파일/문단 |
| **Activity** | 그 항목을 만든 행위(자동 학습·수동 큐레이션·승급) | `출처: auto 자동 승급(코드 검증)` 등 |
| **Agent** | 만든 주체(사람/에이전트/훅) | 책임 주체 명시 |

각 항목은 최소 **(1) 출처 유형, (2) 생성/검증 행위, (3) 날짜** 를 남긴다.

```markdown
> 출처: auto 레인 자동 승급(코드 검증) · 행위: knowledge-audit · 기록: 2026-06-24
```

- **wasDerivedFrom**: 정본이 auto 후보에서 파생됐으면 그 사실을 남긴다(추적성).
- **wasAttributedTo**: 누가/무엇이 만들었는지(사람 vs 기계)를 구분 가능해야 한다.

## 3. 검증 게이트 (verification gate) — 승급의 전제

미검증 → 정본 승급은 **검증 게이트**를 통과해야만 한다. 사람 승인을 코드 실증으로 대체한 경우, 게이트는 다음을 요구한다.

- 항목이 언급하는 **파일/심볼/플래그가 현존**함을 `grep`/`Glob`으로 확인.
- 항목의 `evidence` 헤더가 실제 근거를 가리키는지 대조.
- "맞을 것 같다"는 추정 승급 금지 — **실증된 것만**.

검증 행위와 그 결과(통과/실패)는 provenance에 남겨, 나중에 누가 무슨 근거로 승급했는지 재구성 가능하게 한다.

## 4. 등급 전이 (state transition)

```
unverified ──(근거 부재/틀림)──▶ discard
unverified ──(맥락 부족)──▶ hold(보류) ──(재판정)──▶ ...
auto ──(검증 게이트 통과)──▶ 정본(curated)
auto ──(코드와 어긋남·중복)──▶ discard
```

- 보류(hold) 항목이 여러 패스 살아남으면 신뢰도를 올릴 근거가 된다(자동 폐기하지 않는다).
- 정본 강등은 별도 사건(코드 변경으로 사실이 깨짐) — `staleness-freshness.md` 참조.

## 리뷰 훅

- [ ] 항목마다 **출처 유형(정본/auto/unverified)** 이 명시돼 있는가.
- [ ] **생성·검증 행위와 날짜**(provenance 3요소: entity/activity/agent)가 기록돼 있는가.
- [ ] 미검증/auto 항목을 다른 판단의 **근거로 인용**하고 있지 않은가.
- [ ] 정본으로 승급된 항목은 **검증 게이트(코드 실증)** 를 통과한 기록이 있는가.
- [ ] auto→정본 파생 항목에 **wasDerivedFrom(원본 추적)** 가 남아 있는가.
