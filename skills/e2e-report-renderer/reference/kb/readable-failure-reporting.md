# KB: 읽기 쉬운 실패 보고 / 접근성(WCAG AA)

실패 한 건을 사람이 빨리 이해하고 고치게 만드는 표현 규칙과, 색각·대비 접근성 기준.
근거: WCAG 2.2 Contrast (Minimum) 1.4.3, W3C ARIA(상태 전달 보조).

## 1. 좋은 실패 메시지의 4요소

| 요소 | 의미 | 예시(범용) |
|------|------|-----------|
| **기대(Expected)** | 무엇을 기대했나 | `HTTP 200, body.status == "CREATED"` |
| **실제(Actual)** | 무엇이 왔나 | `HTTP 409, body.error == "OUT_OF_STOCK"` |
| **증거(Evidence)** | 어디서 확인하나 | 응답 본문 인라인, 로그 꼬리, 트레이스 경로 |
| **메시지(Message)** | 사람이 읽는 한 줄 | `재고 부족으로 주문 생성이 거절됨` |

- **기대 vs 실제를 나란히** 보인다. 둘을 떨어뜨리면 진단 속도가 급감한다.
- 증거는 **메시지에서 곧장 도달**할 수 있어야 한다(같은 펼친 행 안에 인라인).
- 모든 `FAIL` 행은 **기본 펼침**으로 둔다(SKILL.md `REN-12`). 실패는 숨기지 않는다.

## 2. 색각 안전: 색 + 글리프 (색만으로 정보 금지)

상태는 **색과 모양(글리프)** 을 함께 써 색각 이상 사용자도 구분하게 한다(SKILL.md `REN-10`).

| 상태 | 색 | 글리프 |
|------|----|-------|
| `PASS` | 초록(green) | `✓` |
| `FAIL` | 빨강(red) | `✕`(굵게) |
| `SKIPPED`(전제 미충족) | 회색(gray) | `–` |
| `PROBE-ERROR` | 호박(amber) | `?` |
| `FAILED-DEPENDENCY` | 호박(amber) | `⤴`(차단 부모 ID 링크) |

- **색만으로 상태를 전달하지 않는다.** 흑백 인쇄·색각 이상·고대비 모드에서도 글리프로
  구분돼야 한다.
- `SKIPPED`(전제 미충족)와 `PROBE-ERROR`를 **별도 옵션/색**으로 구분한다.

## 3. 대비(WCAG 2.2 — 1.4.3 Contrast Minimum)

| 대상 | 최소 대비비 |
|------|------------|
| 일반 텍스트 | **4.5:1** |
| 큰 텍스트(굵게 14pt 이상 또는 18pt 이상) | **3:1** |
| (참고) UI 컴포넌트·그래픽 객체 1.4.11 | 3:1 |

- 상태 색은 **배경과의 대비**가 위 기준을 만족해야 한다. 연한 초록 글자를 흰 배경에 쓰면
  탈락하기 쉽다.
- **검증된 토큰 쌍만 사용**하고 새 색 조합을 즉흥적으로 만들지 않는다(`REN-10`). 새 쌍이
  필요하면 대비를 재계산해 통과를 확인한다.
- 라이트/다크 테마가 모두 있으면 **양쪽 다** 대비를 만족해야 한다.

## 4. 한국어 UI 라벨 + 데이터값 보존

- 사용자에게 보이는 라벨(요약 카드, 필터 placeholder, 표 헤더, 푸터, 빈/오류 상태, 펼친 행
  키 라벨)은 **한국어**가 기본(SKILL.md `REN-11.1`).
- 단, 상태 **데이터값**(`PASS`/`FAIL`/`SKIPPED`/`FAILED-DEPENDENCY`)은 영문 대문자 그대로
  둔다(입력 JSON 계약의 리터럴). 필터 드롭다운만 `통과 (PASS)` 형태로 보여 `dataset.status`
  조인을 깨지 않는다.

## 5. ARIA / 보조기술

- 상태 셀은 색·글리프 외에 **텍스트 라벨**(또는 `aria-label`)을 제공해 스크린리더가
  "통과/실패"를 읽게 한다. 글리프 문자(`✓`)만으론 낭독이 불안정하다.
- 정렬·필터 컨트롤에 접근 가능한 이름(라벨)을 부여한다.
- 펼침/접힘(expand/collapse) 행은 `aria-expanded` 상태를 노출한다.

## 리뷰 훅
- [ ] 각 실패가 기대·실제·증거·메시지 4요소를 모두 보이는가.
- [ ] 기대 vs 실제를 나란히 배치하는가.
- [ ] 모든 `FAIL` 행이 기본 펼침인가.
- [ ] 상태가 색 + 글리프로 표현되어 색만으로 의미를 전달하지 않는가.
- [ ] `SKIPPED`와 `PROBE-ERROR`를 구분하는가.
- [ ] 텍스트 대비가 WCAG AA(일반 4.5:1, 큰 텍스트 3:1)를 만족하는가(검증된 토큰 쌍).
- [ ] 라이트/다크 양 테마에서 모두 대비가 통과하는가.
- [ ] UI 라벨이 한국어이고 상태 데이터값은 영문 대문자로 보존되는가.
- [ ] 상태 셀에 스크린리더용 텍스트 라벨/aria가 있는가.
