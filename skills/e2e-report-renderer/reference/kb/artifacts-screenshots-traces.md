# KB: 실패 아티팩트(스크린샷/트레이스/로그/네트워크)와 임베드 전략

실패를 재현·진단하려면 텍스트 메시지만으로는 부족하다. 증거(evidence) 아티팩트를 어떻게
보존하고 리포트에 넣을지 정리한다. 개념 근거: Playwright Trace Viewer, Allure attachments
(https://allurereport.org/docs/).

## 1. 아티팩트 종류와 용도

| 아티팩트 | 무엇을 담나 | 진단 가치 |
|---------|------------|-----------|
| **스크린샷(screenshot)** | 실패 순간 화면 픽셀 | "무엇이 보였나" — 시각적 회귀, 잘못된 상태 |
| **트레이스(trace)** | 액션·DOM 스냅샷·네트워크·콘솔의 타임라인 | "어떤 순서로 무엇이 일어났나" — 가장 강력 |
| **로그(log)** | 표준출력/표준오류, 애플리케이션 로그 꼬리 | "내부에서 무슨 일이" — 예외 스택, 경고 |
| **네트워크(network)** | 요청/응답(헤더·상태코드·본문) | "통신이 무엇을 주고받았나" — 4xx/5xx, 타임아웃 |

- Playwright **trace**는 액션별 DOM 스냅샷 + 네트워크 + 콘솔 + 소스를 하나로 묶은
  타임라인이며 Trace Viewer로 재생한다. 사후 실패 분석의 1순위 증거다.
- Allure는 이들을 **attachment**(테스트 결과에 첨부된 파일)로 다룬다. 텍스트/이미지/HTML 등
  MIME 타입별로 인라인 미리보기 또는 다운로드로 노출한다.

## 2. 첨부(link) vs 인라인(embed)

| 방식 | 장점 | 단점 |
|------|------|------|
| **첨부(별도 파일 링크)** | 리포트 가벼움, 대용량 가능 | 파일이 분리되면 깨짐, "한 파일 공유" 불가 |
| **인라인(`<pre>`/`data:` 임베드)** | 단일 파일 자급자족, 오프라인 | 크기 증가, 상한 관리 필요 |

- 이 렌더러는 **단일 자급자족 HTML**이 목표이므로 본문·로그 꼬리를 **인라인 임베드**한다
  (SKILL.md `REN-8`). 링크 아티팩트는 "한 파일만 공유" 속성을 깨뜨린다.
- **임베드 범위 제한**: 응답 본문은 시나리오당 head 4KB + tail 4KB, 로그 꼬리는 **실패
  시나리오만**(`REN-8`). 넘치면 `...truncated, see .../raw/` 안내를 보인다.
- 트레이스·스크린샷처럼 무거운 바이너리는 인라인보다 **경로 참조 + 부재 시 열화**가 현실적
  이다(아래 4절). 텍스트성 증거(본문/로그)는 인라인이 적합하다.

## 3. 크기 상한과 단계적 잘라내기

리포트는 4MB 이하를 지향한다(SKILL.md `REN-14`). 초과 시 순서대로 fallback:

1. 시나리오당 인라인 본문을 1KB head + 1KB tail로 축소.
2. 리포트 전체 인라인 로그 합이 200KB 초과면 `FAIL` 시나리오의 로그 꼬리 제거.
3. 그래도 4MB 초과면 **중단**(`REN-14`): run 수를 줄이거나 단일 시나리오 부분집합으로.

- 잘라내기가 적용되면 **푸터에 적용 단계**를 명시해 사용자가 "전부가 아님"을 알게 한다.

## 4. 아티팩트 부재 시 열화(degradation)

- JSON이 `evidence.rawBodyPath`/`evidence.logTailPath`를 참조하는데 파일이 디스크에 없으면
  (예: JSON만 다른 곳으로 복사) 해당 행에 **`(아티팩트 없음)`** 표시를 넣고 인라인 `<pre>`를
  생략한다(SKILL.md `REN-22`).
- 푸터에 **`누락 아티팩트: <건수>`** 한 줄을 추가한다.
- 이는 **렌더를 실패시키지 않는다.** 아티팩트 부재는 알려진 열화 상태이지 데이터 손상이
  아니다(faithful-or-nothing 원칙의 예외: 검증 실패와 정보 부족을 구분).

## 5. 증거에도 마스킹·이스케이프 적용

- 임베드되는 본문·로그·네트워크 텍스트는 **신뢰할 수 없는 캡처 데이터**다(상류 서비스가
  넣은 값). 마스킹(PII)과 XSS 이스케이프를 **반드시** 거친다. 상세는
  `self-contained-html-security.md` 참조.

## 리뷰 훅
- [ ] 본문·로그 꼬리를 링크가 아니라 인라인(`<pre>`)으로 임베드하는가(`REN-8`).
- [ ] 로그 꼬리를 실패 시나리오에만 임베드하는가(통과까지 넣어 비대해지지 않는가).
- [ ] 본문 임베드가 head/tail KB 상한을 지키고 초과 시 truncated 안내를 보이는가.
- [ ] 4MB 초과 시 단계적 잘라내기를 적용하고 푸터에 적용 단계를 명시하는가.
- [ ] 참조된 아티팩트 파일이 없을 때 `(아티팩트 없음)`으로 열화하고 렌더는 계속되는가.
- [ ] 누락 아티팩트 건수를 푸터에 집계하는가.
- [ ] 임베드 전 모든 증거 텍스트에 마스킹·이스케이프를 적용했는가.
