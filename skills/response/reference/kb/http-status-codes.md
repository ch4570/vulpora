# HTTP 상태 코드 의미 (RFC 9110)

> 출처: RFC 9110 §15 (Status Codes). RFC 7231은 RFC 9110으로 대체된 역사적 문서.
> 핵심: **상태 코드는 응답의 의미를 전달하는 계약**이다. 올바른 코드를 골라야 한다.

## 1. 2xx — 성공 (Successful)

| 코드 | 의미 | 사용 시점 |
|------|------|-----------|
| 200 OK | 성공, 본문 포함 | 조회/일반 성공 응답 본문이 있을 때 |
| 201 Created | 리소스 생성됨 | 생성 성공. **`Location` 헤더에 새 리소스 URI** 권장, 본문에 생성 결과 |
| 202 Accepted | 접수됨(비동기) | 처리가 비동기로 시작되어 아직 완료되지 않음 |
| 204 No Content | 성공, 본문 없음 | 삭제 성공/응답 본문이 의미 없을 때(빈 본문) |

- 201은 `OrderResponse`(생성된 주문) + `Location: /orders/{id}`를 함께 반환하는 것이 관용.
- 204는 **본문을 보내지 않는다**(빈 객체 `{}`조차 보내지 않음).

## 2. 3xx — 리다이렉션 (Redirection)

- 301/308: 영구 이동(308은 메서드 보존), 302/307: 임시(307은 메서드 보존).
- 304 Not Modified: 조건부 요청에서 캐시 유효(ETag/If-None-Match).
- API에서는 보통 캐싱/리소스 이동에만 제한적으로 사용.

## 3. 4xx — 클라이언트 오류 (Client Error)

| 코드 | 의미 | 사용 시점 |
|------|------|-----------|
| 400 Bad Request | 요청 자체가 잘못됨 | 파싱 실패, 형식 오류, 일반 검증 실패 |
| 401 Unauthorized | 인증 안 됨 | 자격 증명 없음/무효. `WWW-Authenticate` 헤더 동반 |
| 403 Forbidden | 인가 거부 | 인증은 됐으나 권한 없음 |
| 404 Not Found | 리소스 없음 | 존재하지 않는 리소스(존재 은닉 목적도 포함) |
| 409 Conflict | 상태 충돌 | 중복 생성, 낙관적 락 충돌, 비즈니스 상태 모순 |
| 422 Unprocessable Content | 의미 검증 실패 | 형식은 맞으나 **의미상** 처리 불가(도메인 규칙 위반) |
| 429 Too Many Requests | 레이트 리밋 | 요청 과다. `Retry-After` 동반 권장 |

- **400 vs 422**: 구문/형식 오류는 400, 형식은 맞지만 의미가 안 맞으면 422. 한 API 안에서
  검증 오류를 어느 쪽으로 매핑할지 **하나로 통일**한다(둘 다 흔히 쓰이므로 일관성이 핵심).
- 401 vs 403: 인증 자체 실패=401, 인증됐지만 권한 부족=403.

## 4. 5xx — 서버 오류 (Server Error)

| 코드 | 의미 |
|------|------|
| 500 Internal Server Error | 처리 중 예기치 못한 서버 오류(기본값) |
| 502 Bad Gateway / 503 Service Unavailable / 504 Gateway Timeout | 업스트림/가용성/타임아웃 |

- 5xx 본문에는 내부 상세를 넣지 않는다(→ `error-response-design.md`).

## 5. 멱등성 / 안전성 (RFC 9110 §9.2)

- **안전(safe)**: GET, HEAD, OPTIONS, TRACE — 부작용 없음.
- **멱등(idempotent)**: GET, HEAD, PUT, DELETE, OPTIONS, TRACE — 여러 번 호출해도 결과 동일.
  POST는 멱등하지 않음(중복 생성 → 409 또는 멱등 키로 방어).

## 6. 흔한 실수

- 모든 응답을 200으로 보내고 본문에 성공/실패를 담는 것 → 상태 코드 계약 파괴, 캐시/클라이언트 혼란.
- 생성에 200만 쓰고 `Location` 누락.
- 권한 부족에 404 대신 무조건 403만 쓰거나(은닉 필요시 404), 그 반대로 혼용.

## 리뷰 훅

- [ ] 생성 응답이 201 + `Location` 헤더인가?
- [ ] 본문 없는 성공이 204(빈 본문)인가?
- [ ] 검증 오류를 400/422 중 하나로 **일관**되게 매핑하는가?
- [ ] 인증(401) vs 인가(403)를 올바르게 구분하는가?
- [ ] 상태 충돌/중복에 409를 쓰는가?
- [ ] 모든 오류를 200으로 감싸지 않는가?
- [ ] 5xx 본문에 내부 상세를 노출하지 않는가?
- [ ] 비멱등(POST) 중복 위험을 멱등 키/409로 다루는가?
