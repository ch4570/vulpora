# KB: PII 마스킹과 증거(evidence) 캡처

## 왜 리포트에 마스킹이 필요한가
E2E 리포트는 **공유 아티팩트**다. 레포 경로(`test-report/e2e/...`)·CI 아티팩트·렌더된 HTML로
여러 사람이 본다. 응답 본문/로그에는 실서비스가 다루는 민감 정보가 그대로 흘러들 수 있다.

OWASP Logging Cheat Sheet 핵심(공식 문서):
- **로그/기록에 민감정보를 남기지 마라.** 명시적으로 "절대 로깅하지 말아야 할" 데이터:
  비밀번호·세션 식별자/토큰·접근 토큰·신용카드 등 결제정보·인증 비밀·암호키, 그리고
  법·정책상 보호되는 **PII**.
- 꼭 기록해야 하면 **마스킹/수정(redaction)** 한다.
- 기록 대상 데이터는 **신뢰 경계에서 검증/정제**한 뒤 남긴다(로그 인젝션 방지).

## 무엇을 마스킹하는가 (PII / 비밀 분류)
| 분류 | 예시 | 처리 |
|------|------|------|
| 인증 비밀 | 비밀번호, API 키, JWT/세션 토큰, `Authorization` 헤더 | 전체 제거/치환 |
| 결제정보 | 카드번호, CVV, 계좌 | 전체 제거 또는 마지막 4자리만 |
| 직접 식별자(PII) | 이메일, 전화번호, 주민/여권 번호 | 부분 마스킹(`u***@example.test`) |
| 준식별자 | 정밀 위치, 생년월일 | 정책에 따라 마스킹/일반화 |

- 중립 예시로 다룬다: `Member.email`, `Order.payment.cardNumber`, `Authorization: Bearer ...`.

## 마스킹은 "기록 시점"에 한다 (raw도 마스킹)
SKILL.md `RUN-14`의 강한 규칙:
- 마스킹 클래스를 **기록 직전** 다음 **모두**에 적용한다:
  - Markdown 요약 본문(사람용)
  - JSON `results[*]` 필드(기계용)
  - `raw/` 의 전체 응답 본문
  - `logs/` 의 컨테이너 로그 tail
- **"디버깅용 비마스킹 raw"를 디스크에 남기지 않는다.** 과거에 raw를 비마스킹 저장하던
  관행은 뒤집혔다 — 파일이 공유 경로에 있기 때문. 비마스킹 본문이 필요하면 **해당 단일
  시나리오를 로컬에서 재실행해 터미널에서 관찰**한다. 디스크 산출물은 항상 마스킹.

## 마스킹 클래스 중앙화
- 마스킹 규칙은 러너가 사적으로 들고 있지 않고 **공유 계약(CONTRACT §7)에서 중앙 관리**한다
  (`RUN-14.1`). 러너는 자기만의 비공개 마스킹 목록을 갖지 않는다.
- 앱이 **새 민감 필드 형상**(예: 새 ID 포맷)을 도입하면 **같은 PR**에서 마스킹 클래스를
  추가한다. 분산된 마스킹은 빠뜨린 한 곳에서 누출을 만든다 → 한 곳에서 정의·재사용.

## 증거(evidence) 캡처 — 단언보다 증거
관측된 사실을 남겨야 사후에 누구든 재판단할 수 있다(원칙 5, `RUN-13`).
- **항상 캡처**: HTTP 상태코드, 지연(latency), 응답 헤더, 응답 본문.
- **본문 head+tail**: 본문을 4 KB head + 4 KB tail로 잘라 리포트를 가볍게 한다. 전체가
  8 KB를 넘으면 가운데를 `... <N bytes omitted> ...` 로 대체. 전체 본문은 `raw/`에 보존
  (마스킹된 상태로).
- **로그는 실패 시에만**: 실패 시 마지막 5초 컨테이너 로그를 첨부. 성공 시 로그를 붙이지
  않는다(리포트 비대화 방지).
- **로그 수집 실패는 결과를 바꾸지 않는다**: 컨테이너가 내려갔거나 권한이 없어 로그를 못
  가져오면 `evidence.logUnavailableReason`(`container-not-running`/`container-disposed`/
  `docker-permission-denied`/`unknown`)을 기록하고 진행한다. 결과는 여전히 `FAIL`이며
  `SKIPPED`로 강등하지 않는다 — **로그는 증거이지 전제조건이 아니다**(`RUN-13.1`).

## 리뷰 훅
- [ ] PII/비밀(토큰·비번·카드·이메일·전화)을 분류해 마스킹하는가.
- [ ] 마스킹을 **기록 시점**에, Markdown·JSON·raw·logs **모두**에 적용하는가(`RUN-14`).
- [ ] 비마스킹 raw를 디스크에 남기지 않는가(공유 경로 위험).
- [ ] 마스킹 클래스를 **공유 계약에서 중앙 관리**하는가(러너 사적 목록 금지, `RUN-14.1`).
- [ ] 새 민감 필드 도입 시 같은 PR에서 마스킹 클래스를 추가하는가.
- [ ] 증거로 상태/지연/헤더/본문을 항상 캡처하는가; 본문은 head+tail로 제한하는가.
- [ ] 로그는 실패 시에만 첨부하는가; 로그 미수집 시 사유를 남기고 결과를 강등하지 않는가.
