# KB: 플레이키 테스트(Flaky Tests)

## 정의와 위험
- **플레이키 테스트**: 코드 변경 없이 같은 입력으로 돌려도 **통과·실패가 들쭉날쭉**한 테스트.
  결과가 비결정적이다.
- Google Testing Blog의 핵심 관찰: 플레이키는 **신뢰를 좀먹는다.** 한 번 "가끔 실패해도
  그냥 다시 돌리면 됨"이 되면, **진짜 실패조차 무시**하게 된다("늑대가 나타났다" 효과).
  플레이키한 테스트 결과는 신호가 아니라 잡음이다.
- E2E는 네트워크·외부 시스템·시간·공유 상태를 모두 건드리므로 단위 테스트보다 플레이키에
  **구조적으로 취약**하다.

## 원인 분류 (4종)
| 원인 | 증상 | 전형적 트리거 |
|------|------|--------------|
| **타이밍(timing)** | 가끔만 실패, 부하 높을 때 더 자주 | `sleep(고정)` 후 단언, 너무 짧은 deadline, 비동기 미완료 상태에서 단언 |
| **순서 의존(test ordering)** | 단독 실행은 통과, 묶어 돌리면 실패 | 앞 테스트가 남긴 상태에 의존, 정리 누락 |
| **공유 상태(shared state)** | 병렬/연속 실행 시 간헐 실패 | 같은 DB row·인덱스·캐시 키·전역 변수를 여러 테스트가 동시 변경 |
| **네트워크/외부 의존** | 환경 불안정 시 실패 | 외부 API 지연·타임아웃, DNS, 컨테이너 웜업 미완료, 자원 경합 |

- 추가: **부동소수/시간/로케일/타임존** 등 환경 의존 값, 정렬 보장 없는 컬렉션을 순서로 단언.

## E2E 러너의 대응 철학 — 재시도로 가리지 마라
1. **auto-retry 금지(`RUN-2`).** 자동 재시도는 "가끔 실패"를 "항상 통과"로 위장해 실제
   결함을 운영까지 끌고 간다. 러너는 각 시나리오를 **정확히 1회** 실행한다.
2. **그래서 플레이키는 드러난다.** 러너는 결과를 보정하지 않으므로, 비결정 결과가 그대로
   리포트에 남는다 — 이것이 의도된 동작이다(원칙 7).
3. **bounded polling은 타이밍 플레이키의 정당한 해법**이며 재시도가 아니다: `sleep(고정)`을
   유한 deadline polling으로 바꾸면 "너무 짧아서 실패 / 너무 길어서 느림"을 동시에 해결한다
   (KB `async-and-eventual-consistency`).

## 재현(reproduce)과 격리(quarantine)
Google의 실무 절차를 E2E 러너 맥락으로:
- **재현**: 의심 시나리오를 **단독 실행**(순서 의존 분리), **반복 실행**(타이밍/공유상태
  노출), **부하 하에서 실행**(타이밍 악화)으로 비결정성을 드러낸다. 러너는 사용자가
  명시적으로 단일/부분 실행할 수 있게 한다(`RUN-19`).
- **격리(quarantine)**: 원인을 못 고친 플레이키는 **메인 신호에서 분리**해 빨강 게이트를
  오염시키지 않게 한다. 단 격리는 **임시**이며 추적 대상으로 남긴다 — 격리가 영구
  쓰레기통이 되면 안 된다. 격리/해제는 **카탈로그 차원의 결정**이고, 러너는 자동으로 하지
  않고 사실(어느 시나리오가 비결정인지)만 보고한다.
- 진짜 고침: 타이밍→polling, 순서→독립화+teardown, 공유상태→격리/직렬화, 네트워크→
  Wait Strategy/헬스 게이트(KB `test-environment-and-data`, `ci-integration`).

## 리뷰 훅
- [ ] 비동기 단언이 `sleep(고정)`이 아니라 bounded polling인가(타이밍 플레이키 차단).
- [ ] 각 시나리오가 **단독으로도** 통과하는가(순서 의존 없음).
- [ ] 시나리오가 공유 상태(DB row/인덱스/캐시 키)를 다른 시나리오와 충돌 없이 쓰는가(격리).
- [ ] 외부/네트워크 의존이 **헬스 게이트·Wait Strategy**로 ready를 보장한 뒤 실행되는가.
- [ ] 시간/타임존/랜덤/정렬 미보장 값에 단언이 의존하지 않는가.
- [ ] 실패를 **재시도로 숨기지** 않는가(러너는 1회 실행, `RUN-2`).
- [ ] 드러난 플레이키가 격리되고 **추적 항목**으로 남는가(영구 무시되지 않는가).
