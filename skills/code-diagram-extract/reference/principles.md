# Principles — Code Diagram Extract (헌법)

> 코드 동작을 **충실히 추적**하고 **읽기 쉽게** 그리며 **코드로 바로 이동**하게 만드는 절차의 판단 기준.
> KB가 "방법·규칙"이라면 이 문서는 "통찰·판단 기준"이다. 충돌 시 **KB가 우선**한다.

## Sources
- 제어 흐름 그래프(CFG)·호출 그래프(call graph) 일반 이론 — 정적 추적 근거.
- Mermaid 공식 문서(문법) — 에이전트 번들 KB가 단일 출처. https://mermaid.js.org/
- Vulpora 산출물 규약(앵커 범례 하우스 포맷) — `STANDARD.md`.

---

## 1. 정적 추적이 원칙이다 (trace from source only)
- 실행하지 않고 **소스만 읽어** 경로를 재구성한다. 진입점 → 호출 → 분기 → 루프 → early-return → 예외.
- 모든 단계·앵커는 **실제로 읽은 라인**에 근거한다. Read로 라인 번호를 확인하기 전에는 앵커하지 않는다.

## 2. 추상화 수준을 고른다 (right altitude)
- 사용자가 알고 싶은 건 보통 "큰 흐름"이다. 트리비얼 글루(getter·단순 매핑·로깅)는 부모 단계에 흡수한다.
- 한 다이어그램은 한 추상화 수준을 유지한다. 너무 잘게 쪼개지도, 뭉뚱그리지도 않는다(노드 예산 ≤20).
- 깊이가 필요하면 상위 흐름 1장 + 관심 단계의 하위 상세 1장으로 **분리**한다.

## 3. 타입은 동작의 성격이 정한다 (type follows behavior)
- 제어흐름(분기/루프/예외) → flowchart. 상호작용(호출 순서/동기·비동기) → sequence. 상태 전이 → state.
- 억지로 한 타입에 끼워맞추지 않는다. 동작이 두 성격을 강하게 가지면 작은 다이어그램 2장.

## 4. 앵커는 코드로 가는 다리다 (anchors are the bridge)
- **모든 노드 → 실제 `파일:라인`.** 앵커 없는 노드는 그리지 않는다.
- 경로는 레포 루트 기준 상대경로, 백틱으로 감싼다 — 터미널에서 클릭 시 이동(사용자 핵심 요구).
- 분기·루프·예외의 라벨은 코드의 **실제 조건**을 충실히 요약한다. 추측 조건 금지.

## 5. 불확실성을 표시한다 (mark the unknown)
- 동적 디스패치(인터페이스/오버라이드/DI/리플렉션)로 대상이 불확실하면 **호출부를 앵커**하고 "추정"으로 둔다.
- 정적으로 못 푼 호출, 추적 경계, 마스킹한 비밀은 산출 끝 "미해결/추정" 목록에 모은다.
- 단정과 추정을 섞지 않는다.

## 6. 결정론 (deterministic)
- 같은 입력 → 같은 산출. 노드 ID는 실행 순서(`N1..Nn`), 범례 행 순서도 노드 ID 순, 표기 규약 고정.

## 7. 시각화만 한다 (visualize, not review)
- 동작을 그릴 뿐 평가·비판하지 않는다. 발견한 우려는 노트에 사실로만 적고, 판단이 필요하면 리뷰 에이전트로 넘긴다.
