# KB: 정적 추적 방법

프로그램을 실행하지 않고 **소스만 읽어** 실행 경로를 재구성하는 방법.

## 리뷰 훅 (이걸 점검하라)
- [ ] 진입점과 **멈출 경계**를 먼저 정했는가.
- [ ] 추적한 모든 단계가 **실제로 읽은 라인**에 근거하는가(Read로 라인 확인).
- [ ] 분기(조건)·루프·early-return·예외 경로를 **빠짐없이** 따라갔는가.
- [ ] 동적 디스패치(인터페이스/오버라이드/DI/리플렉션)는 호출부 앵커 + "추정"으로 처리했는가.
- [ ] 추상화 수준을 일정하게 유지하고 트리비얼 글루를 흡수했는가(노드 예산 ≤20).

## 절차

### 1. 진입점 잡기
- 사용자가 지목한 함수/핸들러/흐름을 `Grep`/`Glob`로 찾아 **파일을 Read**한다.
- 진입점 찾는 곳은 언어·프레임워크마다 다르다: 라우트/핸들러 등록부, 데코레이터·어노테이션, `main()`, export된 함수, 이벤트 리스너, CLI 명령 등 — 해당 코드의 관례를 따라 찾는다(특정 스택 가정 금지).

### 2. 경계 정하기 (어디서 멈출지)
- 후보: ① 호출자 스코프의 끝(반환), ② I/O 엣지(DB 저장·외부 API), ③ 외부 시스템.
- 너무 깊이 들어가지 않는다. 외부 라이브러리/프레임워크 내부는 "경계"로 두고 호출부만 앵커.
- 고른 경계를 산출 노트에 명시한다.

### 3. 실행 순서로 따라가기
다음을 **코드에 있는 그대로** 수집한다(없는 흐름 발명 금지):
- **순차 호출**: 메서드 호출을 순서대로. 트리비얼 글루는 부모 단계에 흡수.
- **분기**: `if/else`, `when/switch`, 삼항 — 각 갈래를 노드로, 엣지에 **실제 조건** 라벨.
- **루프**: `for/while/forEach` — 본문을 노드로, 되돌아오는 엣지에 반복 조건 라벨.
- **early-return / guard**: 빠른 반환·검증 실패 경로를 빠뜨리지 않는다.
- **예외 경로**: `throw`, `try/catch`, 에러 반환 — 정상 경로와 구분(점선/별도 노드).

### 4. 호출 대상 해소 (정적 한계 다루기)
- **정적으로 확실**: 구체 클래스의 메서드, 명확한 함수 호출 → 대상 정의 위치를 앵커.
- **동적 디스패치**: 인터페이스/추상 메서드/DI 빈/콜백/리플렉션 → **호출부를 앵커**하고,
  찾을 수 있는 구현 후보를 `Grep`(예: `implements <Interface>`, `: <Interface>`)으로 모아 노트에 "추정"으로.
- 오버로드/오버라이드가 모호하면 단정하지 말고 후보를 적는다.

### 5. 추상화 수준 맞추기
- 한 다이어그램은 한 수준. "주문 저장"이 내부적으로 5단계여도 상위 흐름에선 1노드로, 필요시 하위 다이어그램으로 분리.
- 노드 수가 예산(≤20, 상한 25)을 넘으면 phase로 묶거나 2단 구성으로 분리(가독성 KB).

## 언어별 빠른 팁
- **Kotlin/Java**: 인터페이스+DI가 많다 → 호출부 앵커 + `Grep`으로 구현 탐색. `when`은 분기 노드.
- **TS/JS**: 콜백·프로미스·async/await → 비동기는 sequence의 `-)`/`async` 또는 flowchart 점선으로.
- **Python**: 덕타이핑·데코레이터 → 데코레이터가 흐름을 감싸면 진입 전/후 단계로 표시.

## 인용 시
"정적 추적상 N5는 인터페이스 호출 — 호출부 앵커, 구현은 Grep으로 후보 2개 발견(추정)" 식으로 근거를 단다.
