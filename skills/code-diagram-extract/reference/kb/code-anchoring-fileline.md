# KB: 코드 앵커링 — `파일:라인`으로 바로 이동

사용자의 핵심 요구: **"어느 코드 몇 번 라인인지 보이고, 그 코드로 바로 갈 수 있어야 해."**
모든 노드는 실제 `파일:라인`을 가리키고, 클릭하면 그 라인으로 이동해야 한다.

## 리뷰 훅 (이걸 점검하라)
- [ ] 모든 노드가 앵커 범례에 **1:1로** 대응하는가(누락 노드 0).
- [ ] 각 앵커가 **실제로 Read한 라인**인가(추측 라인 금지).
- [ ] 경로가 **레포 루트 기준 상대경로**이고 **백틱**으로 감쌌는가(터미널 클릭 인식).
- [ ] 형식이 `경로:라인`인가(예: `src/order/OrderService.kt:88`). 범위가 필요하면 `:88-95`.
- [ ] 동적 디스패치 노드는 호출부를 앵커하고 "(추정: 구현 런타임 결정)"을 달았는가.
- [ ] (렌더용) `click` 지시문을 쓰면 `경로#L라인` 형식으로 같은 위치를 가리키는가.

## 앵커 수집·검증
1. 노드가 가리키는 코드 지점을 **Read로 직접 확인**한다 — 화면에 보이는 줄 번호(`cat -n` 형식)를 그대로 쓴다.
2. 한 노드 = 한 핵심 라인(또는 짧은 범위). "이 분기가 시작되는 줄", "이 호출이 일어나는 줄"을 고른다.
3. 파일을 수정하면 라인이 밀린다 — 앵커는 **현재 작업 트리 기준**임을 전제한다(편집 후 재확인).

## 터미널 클릭 포맷 (1차 — 필수)
Claude Code 터미널은 `파일:라인`을 클릭하면 에디터의 해당 라인으로 연다. 그래서 **앵커 범례표**가 핵심 장치다.

```markdown
| 노드 | 코드 위치 (클릭하여 이동) | 설명 |
|------|--------------------------|------|
| N1 | `src/order/OrderController.kt:42` | 주문 생성 요청 진입점 |
| N2 | `src/order/OrderService.kt:88` | 재고 수량 검증 분기 |
| N5 | `src/payment/PaymentClient.kt:55` | 외부 결제 호출 (추정: 구현 런타임 결정 — 호출부 앵커) |
```
- 행 순서 = 노드 ID 순(결정론). 경로는 백틱 필수(클릭 인식·가독성).
- 절대경로/개인 머신 경로 금지(이식성 — `STANDARD.md`).

## 렌더 환경 클릭 포맷 (보조 — 선택)
IDE·GitLab/GitHub MR·마크다운 프리뷰(Mermaid 지원)에서는 **노드 자체**를 클릭 가능하게 만들 수 있다.
```
click N1 "src/order/OrderController.kt#L42" "OrderController.kt:42"
```
- `click <노드ID> "<경로#L라인>" "<툴팁>"`. 터미널엔 안 먹으므로 범례표와 **병행**한다(같은 위치를 가리키게).
- GitLab/GitHub 블롭 링크 규칙(`#L42`, 범위 `#L42-50`)과 호환.

## 동적 디스패치·불확실 대상
- 인터페이스/추상/DI/콜백/리플렉션 호출은 **호출부**를 앵커한다(거기까진 확실하므로).
- 구현 후보가 있으면 설명 칼럼이나 노트에 "추정"으로 함께: "구현 후보 `BasicPay:20`, `VipPay:15`".
- 절대 임의로 한 구현을 단정해 앵커하지 않는다.

## 비밀·PII
- 앵커는 **위치만** 가리킨다 — 코드의 토큰/키/개인정보 **값**을 범례·노트에 옮기지 않는다. 필요시 `***` 마스킹.

## 인용 시
"앵커는 Read로 확인한 라인. 터미널 클릭용 범례표(`경로:라인`)가 1차, 렌더용 `click`(`경로#L라인`)은 보조" 식으로 근거를 단다.
