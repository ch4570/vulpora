# KB: 인사이트 라우팅 — 메모리 vs 규칙 vs 지식

같은 인사이트라도 **어디에 두느냐**에 따라 효력과 수명이 달라진다. 핵심 구분은 두 축이다.

1. **성격**: 사실/맥락(knowledge) 인가, 강제 규범(rule) 인가?
2. **공유 범위**: 팀 정본(SSOT) 인가, 개인 세션 간 메모리 인가?

## 저장소 종류와 그 의미

| 저장소 | 성격 | 공유 범위 | 강제력 |
|--------|------|-----------|--------|
| `.claude/knowledge/<topic>.md` | 사실·맥락·근거 | **팀 SSOT** | 없음(맥락 보강) |
| `AGENTS.md` / 소유 스킬 `SKILL.md` | 규범(MUST/MUST NOT) | 팀, 버전관리 | **있음(바인딩)** |
| 프로젝트 메모리(`./CLAUDE.md`) | 규범+맥락 혼합 | 팀, 레포에 커밋 | 강함 |
| 사용자 메모리(`~/.claude/CLAUDE.md`) | 개인 선호·규범 | **개인, 전 프로젝트** | 개인 한정 |
| 자동 메모리 | 개인 세션 간 리마인더 | 개인 | 약함 |

> Claude Code 메모리는 **import(`@path`)로 계층 구성**되며 상위/하위 디렉터리로 재귀 로딩된다.
> 따라서 "팀 규칙"은 레포에 커밋되는 파일에, "내 습관"은 사용자 메모리에 둔다.

## 라우팅 결정 흐름

```
인사이트
  ├─ 강제 규범인가("항상/절대 ~하라")?  → 예: 규칙 경로
  │     ├─ 언어/프레임워크 코딩 규칙   → 해당 리뷰 스킬 SKILL.md 수정 제안
  │     ├─ 테스트 규칙                  → test-authoring 스킬 SKILL.md 수정 제안
  │     └─ 그 외 일반 규범              → AGENTS.md
  └─ 사실/맥락인가?                     → 예: 지식 경로
        ├─ 팀이 알아야 함               → .claude/knowledge/<topic>.md (SSOT)
        └─ 나만의 세션 간 리마인더      → 사용자/자동 메모리
```

## 규칙(rule) vs 지식(knowledge) 구별 기준

- **규칙**: 위반 시 잘못된 것이 되는 **당위(MUST / MUST NOT)**. 검증·강제의 대상.
  거버닝 문서(`AGENTS.md`)나 스킬에 둬야 효력이 생긴다. 지식 노트에 묻으면 강제력이 없다.
- **지식**: 참/거짓을 다투는 **사실·근거·맥락**. 강제하지 않고 판단을 돕는다.
  규범으로 위장한 지식(또는 그 반대)은 둘 다 약화시킨다.

## 팀 SSOT vs 개인 메모리

- 팀 전체가 재발견을 피해야 하는 것 → **반드시 팀 SSOT**(`.claude/knowledge/` 또는 커밋되는 규칙 파일).
- "나는 이 명령을 자주 잊는다" 같은 **개인 작업 습관** → 사용자/자동 메모리. 팀 SSOT를
  개인 메모로 오염시키지 않는다.
- 스킬을 수정해 규칙으로 승격할 때는 `skill-updater`를 따르고 **KO 동기화를 같은 변경에서** 한다.

## 리뷰 훅

- [ ] 이 인사이트는 규범(MUST)인가 사실(맥락)인가를 먼저 분류했는가?
- [ ] 규범이라면 거버닝 문서/스킬에 두었는가(지식 노트에 묻지 않았는가)?
- [ ] 사실이라면 `.claude/knowledge/`(팀) 또는 메모리(개인)로 **공유 범위**를 맞췄는가?
- [ ] 개인 습관을 팀 SSOT에, 팀 규칙을 개인 메모리에 잘못 넣지 않았는가?
- [ ] 스킬을 규칙 저장소로 수정했다면 `skill-updater` 절차 + KO 동기화를 지켰는가?
- [ ] 사용자 승인 전에 어떤 파일도 수정하지 않았는가?
