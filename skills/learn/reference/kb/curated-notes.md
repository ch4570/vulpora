# KB: 큐레이트 노트 — write-once 품질 규약

영속 지식 노트는 한 번 잘 써서 **오래 살아남는(evergreen)** 것을 목표로 한다.
"일단 적어두고 나중에 정리"가 아니라, **쓰는 순간 재사용 가능한 형태**로 만든다.

## 좋은 노트의 4속성 (Evergreen notes)

1. **원자적(atomic)**: 한 노트 = 한 개념. 분리 가능한 아이디어는 분리한다.
2. **개념 지향(concept-oriented)**: 제목이 곧 주장/개념. "회의 메모"가 아니라 "주장"으로 짓는다.
3. **밀결합·소결합(densely linked)**: 관련 노트끼리 링크해 재발견을 돕는다.
4. **자기 소유의 표현**: 출처를 베끼지 말고 자신의 언어로 압축한다(단, 근거는 명시).

## 필수 메타 — 노트 머리말

```markdown
# <개념을 담은 명확한 제목>
> 출처: <근거(공식문서 URL · 대화/PR · 책장)> · 기록: YYYY-MM-DD
```

- **제목**: 검색·식별 가능한 한 줄 주장/개념. 모호어("기타", "메모") 금지.
- **출처/provenance 줄**: 단정의 근거. 근거 없는 주장 금지. 어디서 알게 됐는지(대화/문서)를 남겨
  나중에 검증·갱신할 수 있게 한다.
- **날짜**: `기록: YYYY-MM-DD`. 내구성 판단과 stale 점검의 기준.

## write-once 작업 규약

1. **쓰기 전 dedup**: 같은 개념의 노트가 이미 있는지 먼저 검색한다(`AGENTS.md`/스킬/
   `.claude/knowledge/`). 있으면 새로 만들지 않는다.
2. **제자리 갱신(update-in-place)**: 기존 노트가 있으면 **수정**한다. 절대 거의-같은 노트를
   복제하지 않는다(중복은 진실의 출처를 둘로 쪼개 drift를 만든다).
3. **원자성 유지**: 갱신하다 노트가 두 개념이 되면 분리한다.
4. **인덱스 갱신**: 새 노트를 만들면 색인(`.claude/knowledge/README.md` 또는 KB `INDEX.md`)에
   한 줄 링크를 추가한다 — 발견 가능해야 지식이다.

## 안티패턴

- 같은 주제로 `notes-1.md`, `notes-final.md`처럼 복제본 양산(SSOT 붕괴).
- 출처 없는 단정. 날짜 없는 노트(stale 판별 불가).
- 한 파일에 인사이트 여러 개를 시간순으로 쌓는 로그형 노트.
- 원문 통째 복붙(압축·개념화 실패).

## 리뷰 훅

- [ ] 제목이 개념/주장을 담은 한 줄인가(모호어 아님)?
- [ ] 출처(provenance)와 `기록: YYYY-MM-DD` 날짜가 머리말에 있는가?
- [ ] 쓰기 전에 dedup 검색을 했는가? 기존 노트가 있으면 **복제 대신 제자리 갱신**했는가?
- [ ] 노트가 한 개념만 담는가(원자성)? 두 개념이면 분리했는가?
- [ ] 새 노트를 색인(README/INDEX)에 한 줄로 등록했는가?
- [ ] 원문 복붙이 아니라 자기 언어로 압축했는가?
