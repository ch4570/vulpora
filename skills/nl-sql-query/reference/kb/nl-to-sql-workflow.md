# KB: 자연어 → SQL 변환 절차

> 정직 라벨: 이 문서의 절차는 **내부 방법론**이다. SELECT 문법 자체는 일반 SQL 표준을 따르며,
> dialect별 차이는 [`dialect-differences.md`](dialect-differences.md)가 단일 근거다.

## 1. 용어 → 스키마 매핑
- NL 명사("주문", "회원", "글")를 후보 테이블·컬럼으로 매핑한다: `search_objects(keyword)`.
- 후보가 여러 개면 `list_tables(schema)`로 범위를 좁히고, `describe_table(schema, table)`로 **정확한 컬럼명·타입·NULL·PK/FK**를 확정한다.
- 동의어·약어(예: "고객" ↔ member, "구매" ↔ order)는 매핑을 명시적으로 가정으로 남긴다.

## 2. 질문을 SQL 절로 분해
질문을 다음 절로 쪼개 매핑한다.

| 질문 요소 | SQL 절 |
|-----------|--------|
| "무엇을" (보고 싶은 값) | `SELECT` (컬럼·집계함수) |
| "어디서" (대상 엔티티) | `FROM` + 필요 시 `JOIN` (FK 근거) |
| "어떤 조건" (필터) | `WHERE` (값은 파라미터 바인딩) |
| "묶어서" (그룹·집계) | `GROUP BY` (+ `HAVING`) |
| "정렬" | `ORDER BY` |
| "몇 개·페이지" | 행 제한 (dialect별: `LIMIT`/`TOP`/`OFFSET..FETCH`) |

## 3. 집계 / 조인 / 필터 규칙
- **집계**: `COUNT/SUM/AVG/MIN/MAX`. 집계 + 비집계 컬럼 혼합 시 비집계 컬럼은 모두 `GROUP BY`에 넣는다.
- **조인**: FK 근거가 있을 때만 조인한다(`describe_table`의 FK). 조인 키·카디널리티를 확인해 행 폭증(카테시안)을 피한다.
- **필터**: 기간·범위·동등/포함 조건. 리터럴 값은 SQL에 박지 말고 `params[]`로 바인딩한다.
- **정렬·페이지네이션**: 결정적 결과를 위해 페이지네이션엔 안정적인 `ORDER BY`(고유 키 포함)를 둔다.

## 4. 모호성 처리
- 기간이 불명확("최근")하면 단위를 가정하지 말고 묻거나, 가정(예: 최근 30일)을 명시한다.
- 집계 단위(일/주/월), 정렬 기준, "상위 N"의 N이 불명확하면 1–2개 명확화 질문을 한다.
- 매핑이 불확실하면(어느 테이블/컬럼인지) `describe_table` 결과를 근거로 후보를 제시하고 확인을 받는다.

## 리뷰 훅
- [ ] NL 용어를 `search_objects`/`describe_table`로 실제 컬럼에 매핑했는가(추측 아님).
- [ ] SELECT/FROM/JOIN/WHERE/GROUP BY/ORDER BY/행제한으로 질문을 절 단위로 분해했는가.
- [ ] 집계 + 비집계 혼합 시 비집계 컬럼을 모두 GROUP BY에 넣었는가.
- [ ] 조인은 FK 근거가 있고 카디널리티(행 폭증)를 점검했는가.
- [ ] 모든 리터럴 값을 파라미터로 바인딩했는가.
- [ ] 기간·범위·정렬·N이 모호하면 가정을 명시하거나 명확화 질문을 했는가.
