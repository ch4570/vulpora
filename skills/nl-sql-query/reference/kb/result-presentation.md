# KB: 결과 제시 규약

> 정직 라벨: 이 문서는 **내부 규약**이다. 실행은 `nl-sql` MCP의 `run_select`가 markdown 표로
> 결과를 반환하며, 이 문서는 그 결과를 사용자에게 **어떻게 제시할지**를 정한다.

## 기본 구성 (항상 함께 제시)
1. **결과 표**: `run_select`가 반환한 markdown 표. 컬럼 헤더가 의미를 드러내도록 별칭(`AS cnt`)을 쓴다.
2. **사용한 SQL**: 코드블록으로 그대로 보여준다. 파라미터를 썼으면 `params` 값도 함께 표기한다.
3. **행수 / 절단 표시**: 반환 행수와, 서버의 자동 행 캡으로 **잘렸는지** 명시한다(예: "상위 100행만 표시 — 더 보려면 조건을 좁히세요").
4. **추정·가정 주의**: NL→스키마 매핑 가정(예: "'상태'를 `order.status`로 가정"), 기간 가정(예: "최근 = 30일") 등을 명시한다.

## 빈 결과 처리
- 0건이면 "결과 없음"을 명시하고 가능한 원인을 제시한다: 필터가 과도, 조인 키 불일치, 컬럼·값 오인.
- 추측으로 SQL을 바꾸지 말고 `describe_table`로 컬럼·타입을 재확인하거나 사용자에게 의도를 확인한다.

## 다건(대량) 처리
- 결과가 행 캡에 닿으면 **잘림을 분명히** 알리고, 더 정밀한 조건(기간·범위·정렬)이나 집계 전환을 제안한다.
- 원시 행 나열보다 집계(COUNT/GROUP BY)가 질문 의도에 맞으면 집계 형태를 우선 제안한다.

## 민감 데이터(PII) 자제
- 이메일·전화·주민/계정 식별자 등 PII는 **필요한 컬럼만** SELECT한다. `SELECT *`로 PII를 과다 노출하지 않는다.
- 질문에 꼭 필요하지 않으면 식별 컬럼을 제외하거나 마스킹·집계 형태를 권한다.

## 제시 예시
질문: "상태별 주문 건수"
```sql
-- PostgreSQL
SELECT status, COUNT(*) AS cnt
FROM "order"
GROUP BY status
ORDER BY cnt DESC;
```
| status | cnt |
|--------|-----|
| PAID | 1240 |
| PENDING | 318 |
| CANCELED | 57 |

- 반환 3행(절단 없음). 가정: '상태'를 `order.status`로 매핑. PII 컬럼 미포함.

## 리뷰 훅
- [ ] 결과 표 + 사용한 SQL(코드블록) + 행수/절단 + 추정·가정을 모두 제시했는가.
- [ ] 파라미터를 썼다면 `params` 값을 함께 표기했는가.
- [ ] 행 캡에 닿았으면 잘림을 분명히 알리고 좁히기·집계를 제안했는가.
- [ ] 빈 결과면 원인 후보를 제시하고 추측 수정 대신 재확인·질문으로 이어갔는가.
- [ ] PII 컬럼을 과다 노출하지 않고 필요한 컬럼만 선택했는가.
