# 통합 체크리스트 & 심각도 루브릭

> 리뷰 최종 점검용. 차원별 체크리스트 + 심각도 판정 기준. 상세 근거는 다른 레퍼런스 참조.

## 심각도 루브릭

| 등급 | 정의 | 예시 | 판정 |
|------|------|------|------|
| 🔴 **CRITICAL** | 보안 취약점, 데이터 손실/손상, **증명된** 동시성 데이터 레이스, 부팅/배포 파손 | 시크릿 하드코딩, SQL 인젝션, 싱글톤 빈 가변 상태, 도메인의 외부호출 무격리, 트랜잭션 내 통화 `Double` | **BLOCK** |
| 🟠 **HIGH** | 버그 가능성, 아키텍처 규칙 위반, 트랜잭션 오류, **증명 가능한** 정합성 결함 | 의존성 방향 위반, `@Transactional` 자기호출, 비즈니스 `!!`, N+1, `GlobalScope`, 블로킹 IO 오디스패처 | **WARN (수정 권고)** |
| 🟡 **MEDIUM** | 유지보수성 저하, 비관용 패턴, SRP 위반, **의도 가능한 동시성/정합성 트레이드오프** | 거대 서비스, 플래그 인자, 공개 `Mutable*`, 수동 루프, 빈약한 도메인, "동시 요청 시 가능"한 정합성 이슈(의도확인 요청) | **INFO (고려)** |
| 🟢 **LOW** | 사소한 개선 (린터가 잡는 기계적 스타일 제외) | `var`→`val` 등 의미적 개선 | **NOTE (선택)** |

**판정 규칙 (게이팅)**:
- **[확정] CRITICAL** → **BLOCK**
- **[추정] CRITICAL** (사실 전제 미확인) → **조건부 BLOCK(검증 필요)** — 단정적으로 막지 말고 검증 명령 실행/제시
- HIGH만 → **WARNING** / 아무것도 없음 → **APPROVE**

### 신뢰도 등급 (각 발견에 태깅)
- **[확정]** — 컴파일/테스트(빌드시스템 자동감지: gradle/maven 등)/결정적 grep·Read로 증명됨.
- **[추정]** — 정적 추론만. 환경/비용 제약으로 미실증. 판정에 [추정] CRITICAL/HIGH가 남으면 **실행할 검증 명령을 함께 명시**한다.

### 🚫 사실 전제 확인 (필수 — 거짓 BLOCK 방지)
CRITICAL/HIGH의 근거 **사실**(빈/클래스 위치, 의존 그래프, `@ComponentScan` 범위, 호출부 존재 등)은
**추측 금지 — grep/Read로 확인한 뒤에만 주장**한다. 미확인이면 `[추정]`으로 낮추고 확인 명령을 제시.
> 실전 교훈: "필요 빈이 X 모듈에만 있다"를 확인 없이 단정 → 실제론 다른 패키지에 존재 → 거짓 CRITICAL.
> 거짓 BLOCK은 정확한 BLOCK만큼 비싸다. 사실 전제부터 `grep -rln 'class <Name>'`로 확인하라.

### 심각도 보정 원칙
- **동시성/정합성**: 정상 경로에서 재현되는 레이스만 HIGH+. "동시 요청 시 가능"하나 의도된 트레이드오프일 수 있으면 **MEDIUM + 의도 확인 요청**(단정 금지).
- **린터 위임**: import 정리·포맷·와일드카드·단순 네이밍 등 Detekt/ktlint/Sonar가 자동으로 잡는 항목은 개별 LOW로 나열하지 말고 **"🔧 린터 위임" 한 줄로 묶는다** → 노이즈·비용 절감.
- **적대적 자기검증**: 출력 전 CRITICAL/HIGH를 반박 시도해 못 이기면 강등/제거.

## 차원 1 — 아키텍처 & 경계 (architecture.md)
- [ ] 의존성 규칙: 도메인이 프레임워크/JPA/Jackson에 의존하지 않는가 (🔴/🟠)
- [ ] application이 구체 어댑터가 아니라 포트(인터페이스)에 의존하는가 (🟠)
- [ ] 외부 SDK/HTTP/MQ 호출이 어댑터로 격리되었는가 (🔴)
- [ ] 포트 시그니처에 벤더/프레임워크 타입이 노출되지 않는가 (🟠)
- [ ] 도메인 불변식이 생성자/도메인 메서드로 보장되는가 (빈약한 도메인 아님) (🟡)
- [ ] Aggregate 간 ID 참조, 바운디드 컨텍스트 경계 준수 (🟠)
- [ ] (MSA) 타임아웃/재시도/서킷브레이커, 멱등성, 이벤트 호환성 (🔴/🟠)

## 차원 2 — 보안 (spring.md 7절, security 규칙)
- [ ] 시크릿 하드코딩 없음 (env/시크릿 매니저) (🔴)
- [ ] 모든 사용자 입력 검증 (`@Valid`/`require`) (🔴)
- [ ] 파라미터 바인딩 쿼리 (SQL 인젝션 없음) (🔴)
- [ ] 인증/인가 적용, 메서드 보안 우회 없음 (🔴)
- [ ] 경로/명령에 미검증 입력 없음 (순회/인젝션) (🔴)
- [ ] 에러/로그에 민감정보·스택트레이스 노출 없음 (🟠)
- [ ] CSRF/레이트리밋(상태 변경·공개 엔드포인트) (🟠)

## 차원 3 — 정확성 & 버그
- [ ] 비즈니스 로직 `!!` 없음, 플랫폼 타입 널 처리 (🟠)
- [ ] 싱글톤 빈에 가변 인스턴스 상태 없음 (🔴)
- [ ] 트랜잭션 경계 정확, 자기호출 함정 없음, 조회 `readOnly` (🟠)
- [ ] 통화/정밀 계산 `BigDecimal` (Double 금지) (🔴/🟠)
- [ ] 경계 조건(빈/단일/최대/off-by-one/null) 처리 (🟠)
- [ ] 예외에 컨텍스트+원인, 삼킴 없음 (🟠)
- [ ] N+1/무제한 조회 없음(페이징) (🟠)
- [ ] 코루틴: `GlobalScope` 없음, 블로킹은 `Dispatchers.IO`, 타임아웃 (🔴/🟠)

## 차원 4 — Kotlin/Spring 관용성 (kotlin-idioms.md, spring.md)
- [ ] `val`/불변성 우선, 공개 API에 `Mutable*` 미노출 (🟡)
- [ ] `data class`/`sealed`+망라적 `when` 활용, 타입 분기 반복 없음 (🟡)
- [ ] 생성자 주입(필드 주입 아님) (🟠)
- [ ] 관용적 컬렉션 연산(수동 루프 아님), 대량은 시퀀스 (🟡)
- [ ] `require`/`requireNotNull`/`check`로 경계 검증, `use {}` 자원 관리 (🟡)
- [ ] 스코프 함수 적절 사용, `Optional` 대신 `T?` (🟡)
- [ ] java.time 사용(Date/Calendar 아님), `Instant` 영속화 (🟠)

## 차원 5 — 유지보수성 (clean-code.md)
- [ ] 의도를 드러내는 이름, 매직 넘버 없음 (🟢/🟡)
- [ ] 함수 작게(한 가지만), 플래그 인자 없음, 인자 ≤3 (🟡)
- [ ] 클래스 SRP, 거대 서비스 없음 (🟡)
- [ ] 중복(DRY) 없음 (🟡)
- [ ] 추상화 수준 일관, 디미터 법칙 (🟡)
- [ ] 주석 처리 코드/불필요 주석 없음 (🟢)
- [ ] 죽은 코드 없음 (🟢)

## 차원 6 — 테스트 (clean-code.md 9장, spring.md 8절)
- [ ] 새 로직에 테스트 존재, 해피패스만 아님 (🟠)
- [ ] AAA(Given-When-Then) 구조, 서술적 이름 (🟡)
- [ ] FIRST: 빠르고 독립·반복가능·자가검증 (🟡)
- [ ] 경계/예외 케이스 테스트 (🟠)
- [ ] 슬라이스/단위 우선(무거운 통합 남발 X), `Clock`/시드 주입 (🟡)
- [ ] 커버리지 80%+ (변경 코드) (🟡)

## 리뷰 마무리 멘트 템플릿
- 잘한 점 1~2개를 먼저.
- 각 발견에 **출처 + 수정 전/후 Kotlin 코드**.
- 트레이드오프/컨텍스트가 있으면 명시(규칙 강요 X).
- 최종 판정(APPROVE/WARNING/BLOCK) 한 줄.

## 리뷰 훅
> 이 파일 자체가 차원별 통합 체크리스트다. 최종 점검 시 위 6개 차원 체크리스트를 순서대로 적용하고,
> 아래 게이팅으로 판정한다.
- [ ] [확정] CRITICAL만 BLOCK으로 판정했는가. [추정] CRITICAL은 "조건부 BLOCK(검증 필요)"로 표기했는가.
- [ ] CRITICAL/HIGH의 사실 전제를 grep/Read로 확인했는가 (거짓 BLOCK 방지).
- [ ] 린터가 잡는 기계적 스타일을 "🔧 린터 위임" 한 줄로 묶었는가.
- [ ] 출력 전 CRITICAL/HIGH를 적대적으로 반박해 못 이긴 항목을 강등/제거했는가.
