# KB: 응집도(Cohesion) · 결합도(Coupling)

설계 품질의 두 축. **응집은 높을수록, 결합은 낮을수록 좋다.** 등급(척도)은 Constantine/Yourdon의
구조적 설계에서 유래해 OO에도 그대로 적용된다. 높은 응집 + 낮은 결합 = 변경 국소화 + 재사용성.

## 응집도 등급 (낮음 → 높음, 위로 갈수록 나쁨)
| 등급 | 의미 | 평가 |
|------|------|------|
| **우연적(Coincidental)** | 아무 관련 없는 것들을 한 모듈에(유틸 잡탕) | 최악 |
| **논리적(Logical)** | "비슷한 종류"라 묶음. 플래그로 분기(`do(flag)`) | 나쁨 |
| **시간적(Temporal)** | 같은 시점에 실행돼서 묶음(`init()`이 무관한 초기화 나열) | 나쁨 |
| **절차적(Procedural)** | 정해진 순서로 실행돼 묶음 | 보통 |
| **통신적(Communicational)** | 같은 데이터를 다루는 작업끼리 | 좋음 |
| **순차적(Sequential)** | 한 작업의 출력이 다음 입력 | 좋음 |
| **기능적(Functional)** | 단 하나의 잘 정의된 작업만 수행 | 최선 |

> 목표는 **기능적 응집**. SRP는 본질적으로 "기능적 응집을 가지라"는 요구다.

## 결합도 등급 (낮음 → 높음, 아래로 갈수록 나쁨)
| 등급 | 의미 | 평가 |
|------|------|------|
| **메시지(Message)** | 파라미터 없이 메시지만(가장 느슨) | 최선 |
| **데이터(Data)** | 필요한 기본 데이터만 인자로 전달 | 좋음 |
| **스탬프(Stamp)** | 레코드/객체 통째로 넘기나 일부만 사용 | 보통 |
| **제어(Control)** | 플래그를 넘겨 상대의 내부 흐름을 조종(`f(true)`) | 나쁨 |
| **공통(Common)** | 전역 변수/공유 가변 상태를 함께 씀 | 나쁨 |
| **내용(Content)** | 다른 모듈의 내부를 직접 들여다보거나 변경 | 최악 |

## 측정 보조 지표
- **CBO**(Coupling Between Objects): 한 클래스가 의존하는 다른 클래스 수.
- **LCOM**(Lack of Cohesion of Methods): 메서드들이 공유 필드를 안 쓸수록 ↑ = 응집 낮음 신호.
- **Fan-in/Fan-out**: 들어오는/나가는 의존. fan-out 과다 = 결합 과다.
- **불안정성 I = Ce / (Ca+Ce)** (Martin): 나가는 의존이 많을수록 불안정 → 추상화로 보호.

## 줄이는 방법
- **응집 ↑**: 플래그 분기 클래스(논리적 응집)를 다형성으로 분리, 한 클래스 = 한 책임(SRP), 무관한 필드/메서드 추출.
- **결합 ↓**: 플래그 인자(제어 결합) 제거 → 메서드 분리; 전역/싱글톤 가변 상태(공통 결합) 제거 → 주입;
  스탬프 결합 → 필요한 값만 전달(데이터 결합); 내용 결합 → 캡슐화로 내부 접근 차단; 추상(인터페이스) 도입.

## 리뷰 훅
- [ ] 한 클래스/메서드가 **하나의 잘 정의된 작업**(기능적 응집)을 하는가. 유틸 잡탕(우연적 응집)이 아닌가.
- [ ] `do(flag)`처럼 **플래그로 동작을 바꾸는** 논리적 응집/제어 결합이 없는가 → 메서드/타입 분리.
- [ ] **전역·싱글톤 가변 상태**를 공유(공통 결합)하지 않는가 → 의존성 주입으로 대체.
- [ ] 객체를 통째로 넘기고 일부만 쓰는 **스탬프 결합**이 없는가 → 필요한 값만(데이터 결합).
- [ ] 다른 객체의 내부 필드를 직접 읽고/쓰는 **내용 결합**이 없는가 → 캡슐화·메서드 위임.
- [ ] fan-out이 과한 클래스가 추상에 의존하도록 보호되었는가(불안정성 관리).
