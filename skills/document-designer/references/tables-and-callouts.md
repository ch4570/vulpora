# Tables and Callouts

## Tables

- Use tables for repeated fields or precise comparison, not for paragraph layout.
- Keep headers short, define units in headers, and align values consistently.
- Prefer several focused tables over one table with too many columns.
- Preserve a text alternative or explanation when a table cannot remain readable at target
  width.
- Do not merge cells in Markdown source; represent grouped data with explicit rows or sections.

## Callouts

Use callouts sparingly and give each a semantic label such as `Note`, `Decision`, `Risk`, or
`Warning`. Do not rely on color or icons alone. Keep the label and content together during
pagination.

## Code

- Use fenced code blocks with a language identifier when known.
- Preserve code exactly unless editing code is part of the request.
- Prefer wrapping comments or shortening surrounding explanation over wrapping commands at
  unsafe positions.
- Require horizontal-overflow or page-width inspection during publishing.
