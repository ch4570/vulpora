# KB: 경계값 분석(BVA) / 동등 분할 / 음성 경로

## 동등 분할 (Equivalence Partitioning, ISTQB)
- 입력(또는 출력) 도메인을 **동등 클래스(partition)** 로 나눈다. 한 클래스 안의 값들은 같은
  방식으로 처리될 것으로 기대되므로, **클래스당 대표값 하나**만 테스트해도 그 클래스를 커버한다.
- 클래스는 **유효(valid) 동등 클래스**와 **무효(invalid) 동등 클래스**로 나뉜다.
- 규칙: 무효 클래스는 **한 시나리오에 하나씩** 검증한다(한 요청에 여러 무효 입력을 넣으면 어느
  것이 거부를 일으켰는지 불명확해짐).

예시(범용): `size` 파라미터가 `@Min(1) @Max(100)` 이라면
| 클래스 | 대표값 | 종류 |
|--------|--------|------|
| 1 미만 | `0`, `-1` | 무효 |
| 1..100 | `20` | 유효 |
| 100 초과 | `101` | 무효 |

## 경계값 분석 (Boundary Value Analysis, ISTQB)
- 결함은 **동등 클래스의 경계**에 몰린다. 따라서 각 경계의 **양쪽 값**을 테스트한다.
- 2-값 BVA: 경계값과 그 바로 바깥값. 3-값 BVA: 경계의 -1/경계/+1.

`@Min(1) @Max(100)` 의 BVA 후보:
| 경계 | 테스트 값 | 기대 |
|------|-----------|------|
| 하한 | `0`(무효) / `1`(유효) | 400 / 200 |
| 상한 | `100`(유효) / `101`(무효) | 200 / 400 |

- 문자열 길이(`@Size(min, max)`), 컬렉션 크기, 날짜 범위, 페이지 번호 등에도 동일 적용.

## 음성/실패 경로 분류 (HTTP 상태 기준)
카탈로그의 행위 한정자(behavior qualifier)와 매핑되는 표준 실패 경로:

| 경로 | 트리거 | 상태 | 카탈로그 한정자 |
|------|--------|------|------------------|
| 인증 실패 | 토큰 없음/만료/권한 부족 | 401 / 403 | `AUTH-FAIL` |
| 검증 실패 | 제약 위반(`@Valid` 등) | 400 | `VALIDATION-FAIL` |
| 미존재 | 없는 리소스 조회 | 404 | `NOT-FOUND` |
| 충돌 | 중복 생성·낙관적 락 위반 | 409 | `CONFLICT` |
| DLQ | 리스너 재시도 소진 | (메시지 DLQ 이동) | `DLQ` |

## 핵심 규율: 코드가 강제하는 것만 시나리오화
> 음성 시나리오는 **컨트롤러/리스너 코드가 실제로 그 제약을 강제할 때만** 생성한다.

1. `VALIDATION-FAIL`은 요청 객체에 `@Valid`/`@NotBlank`/`@Min`/`@Size` 등 **선언된 제약이 있을 때만**.
   제약 그룹마다 1개씩 만든다(`SCA-7`).
2. `AUTH-FAIL`은 엔드포인트/클래스에 `@PreAuthorize`/`@Secured` 같은 **지역 인증 애너테이션이 있을 때만**.
   전역 보안 설정에서 추론 금지.
3. `NOT-FOUND`/`CONFLICT`는 코드가 해당 예외(404/409 매핑)를 던지는 분기가 보일 때만.
4. **코드에 없는 음성 경로를 발명하지 마라.** 발명된 음성 시나리오는 실행 시 거짓 신호를 낸다.
   (BVA/동등 분할로 후보를 넓게 뽑되, 최종 채택은 코드 제약으로 좁힌다.)

## 경계 후보 도출 절차
1. 요청 객체의 각 필드에서 검증 애너테이션을 읽어 동등 클래스(유효/무효)를 식별.
2. 각 무효 클래스마다 BVA 경계값을 1개씩 골라 `VALIDATION-FAIL` 후보로 등록.
3. 인증/존재/충돌 분기를 코드에서 확인해 해당 한정자 후보로 등록.
4. 코드가 강제하지 않는 후보는 폐기. 남은 것만 카탈로그 시나리오로 emit.

## 리뷰 훅
- [ ] 검증 제약(`@Valid`/`@Min`/`@Size` 등)이 **선언된 경우에만** `VALIDATION-FAIL`을 만들었는가.
- [ ] 각 무효 동등 클래스에 대해 **경계값(BVA)** 으로 테스트 값을 골랐는가(임의 중앙값 아님).
- [ ] 한 음성 시나리오에 **무효 입력 하나만** 넣었는가(복수 위반 혼합 금지).
- [ ] `AUTH-FAIL`이 **지역 인증 애너테이션**에 근거하는가(전역 설정 추론 아님).
- [ ] `NOT-FOUND`/`CONFLICT`가 코드의 실제 404/409 분기에 대응하는가.
- [ ] **코드에 없는 음성 경로를 발명하지 않았는가**(`SCA-7` 하한선 준수).
- [ ] **source inventory의 모든 required behavior가 exact target 시나리오로 검증됐는가**(`SCA-19`).
- [ ] 각 음성 경로가 관측 가능한 상태코드/효과로 단언되는가.
