# KB: 타임라인 & 증거

좋은 회고·포스트모템은 **사실의 타임라인**에서 시작한다. 원인·해석은 그 위에 쌓는다.
사실 수집 전에 원인을 단정하면 확증편향에 빠진다(principles §2).

## 타임라인 재구성

- 시각순으로 "무슨 일이 있었나"만 적는다(해석 금지). 예: 탐지 시각, 첫 대응, 변경 배포,
  복구 시각.
- 각 항목에 **증거 출처**를 단다(어느 로그/커밋/대시보드에서 나왔는지).
- 빈칸·불확실은 "불명" 또는 "가설"로 명시한다. 메우려고 추측을 사실처럼 쓰지 않는다.

## 증거 수집 (작업 회고 맥락)

작업/세션 회고에서는 git이 1차 증거원이다.

```bash
git log --oneline -20                       # 최근 작업 흐름
git diff --stat HEAD~5 2>/dev/null || git diff --stat   # 변경 규모(파일·라인)
git log --since="1 day ago" --oneline       # 기간 한정
git log --pretty=format:'%h %ad %s' --date=iso   # 정확한 시각 타임라인
git diff HEAD~1 -- <path>                    # 특정 변경 내용 확인
```

- 커밋 메시지·타임스탬프 = 시각 증거. 변경 파일·라인 수 = 작업 규모·churn 신호.
- 빌드/테스트 실패는 로그에서 **실제 에러 메시지**를 인용한다(기억에 의존 금지).

## 사실 vs 해석 분리

| 사실(증거 있음) | 해석/추정(검증 필요) |
|----------------|---------------------|
| "테스트 X가 NPE로 3회 실패"(로그) | "원인은 초기화 순서로 추정" |
| "커밋 5개, +400/−120 라인"(git) | "범위가 너무 넓었던 듯" |

- 해석은 `추정:`/`가설:`로 표기하고, 검증이 필요하면 액션 아이템을 만든다
  (KB: action-item-tracking).

## 흔한 오류

- **기억 의존**: "아마 ~였다" → git/로그로 확인한다.
- **타임라인 생략하고 원인부터**: 사실 골격 없이 분석하면 빈틈을 추측으로 메운다.
- **증거 미인용**: 단정은 출처를 단다(어느 커밋/로그). 출처 없는 주장 금지(principles §2).
- **선택적 증거**: 자기 가설에 맞는 증거만 고르지 않는다(확증편향).

## 리뷰 훅

- [ ] 타임라인이 시각순 사실로 적혔는가(해석 섞이지 않았는가).
- [ ] 각 타임라인 항목·단정에 증거 출처(커밋/로그/지표)가 있는가.
- [ ] 사실과 해석/추정이 표기로 구분됐는가.
- [ ] 빌드·테스트 실패를 실제 에러 메시지로 인용했는가(기억 아님).
- [ ] 불확실한 부분을 추측으로 메우지 않고 "불명/가설"로 남겼는가.
- [ ] git log/diff 등 1차 증거를 실제로 수집했는가.
