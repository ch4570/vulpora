# KB: 액션 아이템 추적

회고·포스트모템의 가치는 **실행되는 개선**에서 나온다. 발견(finding)을 추적 가능하고 소유자가
있고 기한이 있는 액션 아이템으로 바꾸지 못하면, 같은 문제가 재발한다.

## 발견 → 액션 변환

각 발견(Problem/원인)마다 다음을 결정한다:

| 필드 | 질문 |
|------|------|
| 무엇(What) | 정확히 무엇을 바꾸는가 (검증 가능한 행동) |
| 소유자(Owner) | 단 한 명의 책임자 (팀이 아니라 개인) |
| 기한(Due) | 언제까지 |
| 검증(Verify) | 완료를 어떻게 확인하나 |
| 우선순위 | 재발 위험·영향 기준 |

## SMART 기준

- **Specific** — 모호하지 않게. "모니터링 개선"❌ → "Order 적재 잡에 실패 경보 추가"✅
- **Measurable** — 완료 여부를 객관적으로 판정 가능.
- **Achievable** — 현실적 범위. 거대한 항목은 잘게 쪼갠다.
- **Relevant** — 실제 원인을 다룬다(증상 미봉책 금지).
- **Time-bound** — 기한이 있다.

## "절대 일어나지 않는 액션 아이템" 막기

- **소유자 없는 항목 금지**: "누군가 해야 함"은 아무도 안 한다. 개인 1명을 지정한다.
- **추적 시스템에 올린다**: 회고 문서 안에만 두지 말고 이슈 트래커에 티켓으로 만든다.
  보이지 않으면 잊힌다.
- **다음 회고에서 점검**: 지난 액션 아이템의 진행 상태를 회고 첫 단계에서 리뷰한다.
- **양 제한**: 한 회고에서 1~2개의 실행 가능한 항목에 집중. 10개를 적으면 0개가 실행된다.
- **임시 vs 영구 수정 구분**: 즉시 완화(mitigation)와 근본 수정(prevention)을 나눠 둘 다 추적.

## 예방 vs 완화

- **완화(mitigation)**: 지금 당장 피해를 줄이는 임시 조치.
- **예방(prevention)**: 재발 자체를 막는 근본 조치. 회고의 최종 목표는 예방 액션이다.
- 완화만 적고 예방을 빠뜨리면 같은 사고가 반복된다.

## `/retro` 하네스 개선과의 연결

`/retro`에서 도출된 반복 마찰은 액션 아이템이자 **영구적 하네스 변경 제안**으로 분류한다
(컨텍스트/스킬/에이전트/가드레일/검증). 승인된 항목만 반영하며 각각 소유·기한을 갖는다.

## 리뷰 훅

- [ ] 모든 액션 아이템에 단일 소유자가 있는가(팀이 아닌 개인).
- [ ] 각 항목에 기한이 있는가.
- [ ] 각 항목이 검증 가능한가(완료 판정 기준이 명확한가).
- [ ] 회고 문서 밖 추적 시스템(이슈 트래커)에 등록됐는가.
- [ ] 한 회고의 액션 수가 실행 가능한 범위(1~2개 권장)인가.
- [ ] 완화책뿐 아니라 재발 방지(예방) 액션이 있는가.
- [ ] 지난 회고의 액션 아이템 진행 상태를 점검했는가.
