# Support

Vulpora is maintained by an open-source community. Support is best effort and
does not include a guaranteed response time.

## Where to ask

- Use the **bug report** issue form for reproducible incorrect behavior.
- Use the **support question** issue form for installation, configuration, or
  usage questions that are not confirmed bugs.
- Use the **feature request** or **capability pack proposal** form for new work.
- Use GitHub private vulnerability reporting for security concerns, as described
  in [SECURITY.md](SECURITY.md).

Search open and closed issues before filing a new one. Keep one problem per issue
and include the output of `vulpora version`, runtime and scope, operating
system, shell, Node.js version, installation method, exact command, and the
smallest safe reproduction.

Redact access tokens, cookies, database connection strings, private hostnames,
usernames, home-directory paths, proprietary source, and sensitive tool output.
When a log is large, reduce it to the lines needed to explain the failure.

## Scope

Maintainers can help with behavior implemented in this repository. Questions
about a host runtime, database, browser, or third-party MCP service may need to be
raised with that upstream project after Vulpora-specific behavior is ruled out.
Custom capability packs and organization-specific policies are supported by
community discussion, but maintainers are not responsible for operating them.
