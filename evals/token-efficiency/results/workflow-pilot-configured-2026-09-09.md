# 명시적 workflow pilot — 설정 호환성 수정 후, 2026-09-09

판정은 **INCONCLUSIVE / 채택 보류**다. 실제 사용량은 계측했지만, 계획한 9개 작업 중 3개만
실행했고 모두 파일 변경 범위 검사를 실패했다. 완료 작업당 절감이나 일반적인 workflow 우위를
입증하지 못했다. 전역 workflow·모델·예산 기본값은 바꾸지 않는다.

과제·oracle·회귀 결함 검사·순서·모델·수리 기회·중단 한도는 이전 pilot와 동일하다.
두 원본 JSON의 `source`에 기록된 7개 파일 hash도 같다. 이전 실패를 덮어쓰거나 성공한 반복으로
다시 분류하지 않았다. 새 비교에서도 요청 모델은 `gpt-5.6-terra`, effort는 `medium`이다.

설정 오류를 해결하려고 로컬 원본을 백업한 뒤 현재 CLI가 지원하지 않는 최상위 `network_access`와
`features.child_agents_md`를 제거했다. `[env]`의 유일한 값인 `USE_OMX_EXPLORE_CMD`는 값을 유지해
지원되는 `shell_environment_policy.set`으로 옮겼다. 이 위치는 명시적 환경 변수 값을 설정하는
[공식 설정 항목](https://learn.chatgpt.com/docs/config-file/config-reference#configtoml)이다.
그 밖의 설정 바이트는 보존했고, `codex features list`의 유효 기능 상태 135개가 전후 동일했다.
실험 중 CLI가 추가한 임시 작업 공간의 신뢰 등록 3개는 실행 후 제거했다. 기존 프로젝트 등록과
다른 설정이 백업 대비 그대로인지 바이트 단위로 다시 확인했다.
권한·인증 설정이나 필수 host 정책을 제거하지 않았다. 설정 원본과 인증 자료는 결과물에 복사하지 않았다.

같은 실행 옵션에 빈 stdin을 넣은 진단은 설정 오류 대신 `No prompt provided via stdin`으로
끝났다. 이는 모델 호출이나 과금 증거가 아니라 설정 파싱을 통과한 증거다.

`onlyAllowedFilesChanged`는 실패했다. 변경 목록에 과제 파일 외의 `.omx/logs/*`, `.omx/state/*`,
`.omx/metrics.json`이 포함됐다. 원본은 변경 경로를 보존하지만 생성 주체를 입증하지 않으므로,
모두 host가 만들었다거나 모델이 만들었다고 단정하지 않는다. 관측 후 `.omx`를 허용 목록에
추가해 통과로 바꾸지 않았다. 다른 여섯 gate는 세 조건 모두 통과했다.

범위 밖 변경이 있는 실패에는 규약상 수리를 허용하지 않아 수리 시도는 0회다. 같은 안전 gate가
산출물 내보내기도 거부했으므로 세 실패의 patch는 저장되지 않았다. 원본의 `artifact.saved:false`와
거부 사유를 유지했다. 원본 카운터·검사 결과·실패·변경 경로는 보존했으며, patch나 raw 대화가
보존됐다고 주장하지 않는다. `.omx` 로그 내용도 결과물로 내보내지 않았다.

두 번째 호출 후 누적 502,933토큰은 600,000 미만이어서 세 번째 호출이 허용됐다. 세 번째 호출 후
645,777토큰이 되어 `AGGREGATE_TOKEN_GUARD`가 추가 실행을 막았다. 사전 규약대로 한 호출만큼
한도를 초과할 수 있으며, 이번 초과분은 45,777토큰이다. 제공자 강제 한도로 표현하지 않는다.
테스트 작성·리뷰 과제의 나머지 6개 작업은 미실행이다. 각 조건의 `unstartedRuns`는 2다.
전체 실행 구간은 237.735초이며, 사전 설치·발견 검사 시간은 이 값에 포함되지 않았다.

## 비용과 완료 판단의 경계

새 pilot의 3개 호출 사용량은 모두 관측됐다. 다만 이전 시작 실패의 사용량은 여전히 `unknown`이다.
두 pilot를 합친 비용 기록은 **총 4개 실행 시도 중 알려진 소계 645,777토큰**, 전체 토큰·비용은
`null`로 유지한다. 두 계획을 합친 미실행 작업은 14개다. 개선·감독·독립 검토 모델 사용량, 설치
시간, 엔지니어링 비용과 실제 청구도 미계측이며 0으로 넣지 않았다.

검증된 완료 작업이 0건이므로 완료당 토큰·비용은 정의되지 않는다. 시도별 토큰 차이를 완료당
절감률로 바꾸지 않는다. cache는 통제하지 않았고, 실제 backend·service tier·요청별 context 길이와
설치 패키지 출처는 attestation으로 확인하지 않았다. 회수 작업 수와 품질 우위도 미확정이다.

이 pilot는 작은 예산에서 사용량·실패·중단을 실제 계측한 기록이다. **9개 작업의 전체 비교 완료,
실제 청구 절감, live 자식 호출 집계, 사람의 의미 기반 리뷰 품질은 검증하지 못했다.** 후속 비교는
host 산출물의 소유권과 작업 파일 범위를 먼저 규약으로 고정하고 새 과제 예산을 검토해야 한다.
이번 결과를 개선하기 위해 한도를 초기화하거나 실패 판정을 바꾸지 않는다.
