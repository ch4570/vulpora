# Luna 활용 및 난이도별 라우팅 실측 — 2026-09-07

**라우팅은 실행됐지만, 토큰 절감과 더 높은 완성 품질을 함께 달성했다는 제품 목표는 미달이다.**
이번 표본에서 자동 라우팅은 Terra 고정보다 Standard API 기본 환산비용이 25.6% 낮았고,
총토큰은 7.8% 많았다. Luna 단독은 네 작업 모두 통과하면서 토큰 5.9%, 기본 환산비용 87.7%를 줄였다.
LRU 생성 테스트의 추가 결함 탐지력은 Luna 6/8, Terra 고정 7/8, 라우팅의 Terra 실행 8/8이었다.
이 한 사례는 완료 여부만으로 보이지 않는 테스트 품질 차이를 보여주지만 모델의 일반적 우열을 입증하지 않는다.

## 구현한 선택 규칙

| 작업 사실 | 기본 선택 |
|---|---|
| 단순하고 위험이 낮은 구현·조회·문서·검토·테스트 | Luna / low |
| 중간 난이도; 범위가 정해진 복잡한 구현 | Terra / medium |
| 복잡한 아키텍처·연구; 높은 실패 위험 | Frontier, Astra / high부터 |
| 결정적 검사 | 모델 호출 없음 |

분류는 호출자가 제공한 작업 종류·난이도·위험을 사용하는 규칙이며 별도 모델을 부르지 않는다.
가용 catalog와 사용자 정책·예산을 적용한다. 작은 작업은 기존 상위 세션이 직접 처리하는 규칙을 유지한다.
상위 검증자가 모델 품질 실패를 확인한 경우에만 `resolveTaskEscalation()`이 다음 단계와 정지 사유를
반환한다. 관측 사용량·정산 예산이 필요하고 Luna → Terra → frontier의 전체 세 번 또는 더 작은 사용자
상한을 지킨다. 환경·권한 문제, 원인 불명, 사용량 미관측, 명시적 profile 고정에서는 자동 상향하지 않는다.
세션 task의 선택적 `profile`로 검증된 다음 시도를 준비할 수 있으며 transport 자체는 자동 재시도하지 않는다.

## 실험 조건과 결과

[고정 규약](../ROUTING-EVAL.md)의 네 fixture를 세 방식으로 한 번씩 새로 실행했다. 각 작업의 최대
시도는 두 번, 전체 토큰 admission guard는 1,200,000개였다. 실제로는 모두 첫 시도에 통과하여 총
12회 호출, 재시도 0회였다. 자동 경로는 단순 작업 두 개에서 Luna, 나머지 두 개에서 Terra를 실행했다.
라우터의 상향 정책은 오프라인으로 검증했으며 이번 유료 실행에서는 상향 복구 능력을 시험하지 못했다.

| 방식 | 고정 검사 통과 | 실제 입력+출력 토큰 | 작업당 평균 | Standard API 기본 환산액 / 네 작업 | 캐시 쓰기 포함 시나리오 범위 |
|---|---:|---:|---:|---:|---:|
| Terra 고정 | 4/4 | 194,543 | 48,635.75 | $0.176629 | $0.176629–0.196316 |
| Luna 고정 | 4/4 | 183,090 | 45,772.50 | $0.021723 | $0.021723–0.024584 |
| 자동 라우팅 | 4/4 | 209,783 | 52,445.75 | $0.131387 | $0.131387–0.146029 |

| 문제 | Terra 고정 토큰 | Luna 고정 토큰 | 자동 라우팅 토큰 | 자동 선택 |
|---|---:|---:|---:|---|
| 유한한 양수 판별 | 45,825 | 39,590 | 39,419 | Luna |
| Query 변환과 URL 인코딩 | 48,840 | 54,108 | 52,721 | Luna |
| LRU 상태 관리 | 48,918 | 43,985 | 49,878 | Terra |
| 비동기 재시도와 client 연결 | 50,960 | 45,407 | 67,765 | Terra |

자동 라우팅의 retry 작업은 Terra 고정과 같은 모델·effort·요청을 사용했다. 두 실행의 토큰 차이는
단일 실행 변동도 포함하므로 난이도 라우팅 자체가 7.8%를 증가시켰다는 인과 추정으로 해석하지 않는다.
다만 관측된 총량이 증가했다는 사실 때문에 이번 실행의 토큰 절감 성공을 주장할 수 없다.

관측 입력/캐시 입력/출력은 Terra 고정 188,878/149,504/5,665개, Luna 고정
176,512/119,296/6,578개, 자동 라우팅 203,246/149,504/6,537개였다. 캐시 입력은 입력의 부분집합이며
추가 합산하지 않았다. 모든 시도의 provider `turn.completed.usage`를 집계했다.

## 품질의 구체적 차이와 한계

고정 수락 기준은 외부 동작 검사, 생성된 테스트 실행, 회귀 변형 검사, 변경 파일 제한을 포함하며
12회 모두 통과했다. 이후 생성 테스트를 공통의 독립 LRU 참조 구현과 사전에 정의한 8개 결함에 적용했다.
이 추가 검사는 기존 수락 결과를 바꾸지 않으며 후보 구현 자체의 결함 수를 나타내지도 않는다.

| 추가 결함 검사 | Luna | Terra 고정 | 자동 경로의 Terra |
|---|---:|---:|---:|
| 탐지 수 | 6/8 | 7/8 | 8/8 |
| 놓친 결함 | 없는 키 조회가 항목을 삽입; 저장한 undefined의 존재를 잃음 | 없는 키 조회가 항목을 삽입 | 없음 |

세 테스트 모두 정상 참조 구현에서는 통과했고, 후보 파일 해시가 실측 최종 결과와 일치했다.
8개 결함과 살아남은 변형을 모두 [진단 결과](routing-lru-test-sensitivity-2026-09-07.json)에 보존했다.
Terra 고정과 자동 경로의 LRU 모델은 동일하므로 7/8과 8/8의 차이를 라우터의 인과 효과로 주장하지 않는다.
Luna 단독의 검증 비용·누락 위험을 함께 볼 구체적 사례이며, 넓은 품질 우월성 주장은 추가 표본이 필요하다.

## 비용과 회수 조건

이번 12회에 **587,416토큰**, Standard API 환산 **$0.329739–0.366928**을 사용했다.
이는 실제 결제 명세가 아니다. 개발 대화·검토 에이전트·이전 실험 비용은 이 새 비교에 포함되지 않는다.
같은 성공률과 사용량 분포가 앞으로 유지된다는 가정에서 이번 실험 비용만 회수하려면 Terra 고정 대비
자동 라우팅은 21–48개의 후속 완료 작업, Luna 고정은 8–10개가 필요하다. Luna 고정 대비 자동 라우팅의
금전적 이익은 이번 표본에서 없다. 이 수치를 전체 개발 투자 회수나 미래 절감 보장으로 사용하지 않는다.

모델마다 관측된 입력/캐시/출력에 [공식 API 가격](https://developers.openai.com/api/docs/pricing)을 적용했다.
Standard의 100만 토큰당 입력/캐시 읽기/캐시 쓰기/출력은 Luna $0.20/$0.02/$0.25/$1.20,
Terra $2/$0.20/$2.50/$12다. 캐시 쓰기 미관측량은 0부터 비캐시 입력까지의 추가요금 범위로 남겼다.
Fast 시나리오는 별도로 계산 파일에 보존했다. 서비스 등급, 실제 청구, provider 내부 모델 식별은 확인하지 않았다.

## 증거와 재현

실험은 작업 진입 시 production task/model router를 호출하고 선택한 모델로 새 primary CLI 세션을 실행했다.
호출 설정과 route는 12/12 일치했고 원본 코드·정책·fixture 해시는 실행 중 바뀌지 않았다(`comparable: true`).
전체 `start-task` 설치, Audit, session-runner 캡슐 워크플로우의 효과를 측정한 것은 아니다.
전역 런타임 문맥, 공유 캐시, 세 과제에 대한 과거 실험 노출은 통제하지 못했다. 네 개의 작은 합성 과제와
작업별 한 번의 관측으로 실무 전체 난이도 경계나 일반 품질을 확정하지 않는다.
