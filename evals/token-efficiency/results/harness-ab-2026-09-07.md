# 하네스 적용·미적용 실제 토큰 비교 — 2026-09-07

작은 함수 구현 문제를 같은 모델·추론 설정으로 각각 두 번 실행했습니다. 미적용은 평균
**45,784토큰**, 전체 설치와 `$start-task` 호출 조건은 **121,152토큰**을 사용했습니다.
관측된 차이는 **+75,368토큰, +164.6% (2.646배)**입니다. 네 결과 모두 기능 검증을 통과했습니다.
이는 한 문제의 예비 관측이며, 아래의 스킬 로딩 증거 부족으로 엄격한 절차 준수 판정은
통과하지 못했습니다. [원본 측정 JSON](harness-ab-2026-09-07.json)의 `comparable: false`를 유지합니다.

## 조건과 범위

- 문제: 기존 `absolute`를 보존하면서 유한한 양수에만 참을 반환하는 `isPositive`와 회귀 테스트 추가.
  소스와 테스트 두 파일만 변경하며 `node --test` 실행.
- 요청 모델/추론: `gpt-5.6-terra` / `medium`, Codex CLI `0.153.4`.
  공급자의 실제 백엔드 모델 신원을 별도로 확인한 것은 아닙니다.
- 미적용: Vulpora를 설치하지 않은 새 프로젝트에서 동일한 작업 지시.
- 적용: 새 프로젝트에 `all-agents all-skills` 설치 후 작업 지시 앞에 `$start-task` 추가.
- 실행 순서: 미적용 → 적용 → 적용 → 미적용. 매번 같은 초기 소스·테스트로 시작.
- 공통 설정: `tool_output_token_limit=2000`, 단일 에이전트, 네트워크 검색 비활성화,
  동일한 호스트 설정. 전역 설정이나 인증 파일은 변경하지 않았습니다.
- 모델 호출 없는 사전 확인에서 발견된 Vulpora 스킬은 미적용 0개, 적용 62개였습니다.
  기본 시스템 스킬은 양쪽에 존재하므로 미적용도 기본 Codex 실행 환경을 사용합니다.

추론 토큰도 출력에 중복 합산하지 않았습니다. 이 대화와 측정 도구를 만드는 데 쓴 토큰은 제외합니다.
실행 준비·설치·사후 검증은 모델을 호출하지 않는 도구로 수행했습니다.

평균 비캐시 입력은 미적용 10,222, 적용 20,982.5토큰입니다. 공급자 캐시를 격리하지 않았으므로
실행 순서의 영향이 남습니다. **총 토큰 2.646배를 청구 비용 2.646배로 해석할 수는 없습니다.**

## 결과 검증과 해석의 한계

네 실행 모두 작성된 테스트, 별도의 고정 정답 검사, 허용 파일 범위 검사를 통과했습니다.
회귀 테스트가 무의미하지 않은지도 확인했습니다. `isPositive`를 항상 참 또는 항상 거짓으로
바꾸는 두 변형에서 네 실행의 테스트가 모두 실패했습니다.

적용 실행 두 번 모두 lightweight 실행 경로 선택기를 실제 실행했습니다. 다만 사전에 정한
엄격한 판정은 진입 `SKILL.md` 로딩, lightweight 참조 읽기, 선택기 실행의 증거를 모두 요구합니다.
진입 파일 로딩은 두 실행 모두 확인되지 않았고, lightweight 참조 읽기는 실행 2에서만
확인됐습니다. 런타임의 자동 로딩이나 명령 표현 방식 때문에 관측에서 빠졌을 가능성도 있지만,
원본 실행 스트림을 보관하지 않았으므로 이를 사후에 확인하거나 성공으로 바꾸지 않습니다.

따라서 이 수치는 **전체 설치·명시적 호출 조건에서 관측된 사용량**입니다. 완전한 절차 준수를
입증한 비교나 일반적인 절감률은 아닙니다. 적용 조건에서는 사전 확인 문맥이 9,406바이트에서
29,199바이트로 커졌고, 완료된 셸 명령 수도 각 실행 2개에서 4개로 늘었습니다. 문맥과 절차의
추가 비용이 의심되지만, 사전 확인 바이트는 실제 모델 입력 토큰이 아니며 증가분 전체를
스킬 목록 하나의 원인으로 돌릴 수는 없습니다.

이 문제는 상위 세션이 직접 처리하는 작은 작업입니다. 독립 세션의 모델 라우팅·공유 예산·압축된
결과 반환 효과는 측정하지 않았습니다. 앞서 보고한 프롬프트·상태 응답 문자열의 토큰 감소율도
이처럼 전체 문제 해결에 사용한 토큰의 감소율과 구별해야 합니다.

## 재실행

[실행 스크립트](../run-harness-ab.js)는 아래처럼 명시적으로 실행할 때만 실제 모델을 호출합니다.
기존 결과 파일을 덮어쓰지 않으므로 새로운 출력 경로를 지정해야 합니다.

```sh
node evals/token-efficiency/run-harness-ab.js --run --out /tmp/vulpora-harness-ab-new.json
```

현재 체크아웃을 설치하므로 이후 코드가 바뀌면 조건도 바뀝니다. 사전 확인 후 최대 네 번의
모델 실행을 수행하며 각 실행의 사용량과 검증 결과를 저장합니다. 실행 시간 제한과 실행 사이의
누적 사용량 점검은 실제 청구 토큰의 강제 상한이 아닙니다. 기본 오프라인 테스트에서는 호출하지 않습니다.
